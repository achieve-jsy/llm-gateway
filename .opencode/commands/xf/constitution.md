创建或修订项目宪章，定义项目级别的不可违背原则。

宪章只关注**原则级约束**（绝对不能违反的规则），不涉及具体技术选型细节、质量指标阈值或设计规范——那些在 `/xf/product`、`/xf/design` 等后续阶段决定。

## 用户输入

```
$ARGUMENTS
```

## 前置条件

- `.xflow/` 目录必须存在（框架：templates + scripts，不存在则提示先执行 `xflow init` 初始化项目）
- 如果 `xspec/modules/`、`xspec/changes/`、`xspec/archive/` 不存在，先执行 `node .xflow/scripts/xf-init.mjs` 创建

## 步骤 0：Profile 分支加载（始终先于其他步骤执行）

**注意**：本命令是**第一个**写入 constitution.md 的命令，因此 profile 状态要**先判断文件是否存在**再决定怎么打印，避免在"场景一"里把默认值 `general` 当成既成事实先宣布一遍误导用户。

1. 检测 `xspec/constitution.md` 是否存在：
   - **不存在（场景一：首次创建）** → **不要**执行 `xf-profile.mjs`，**不要**打印 `project_profile = general`；直接打印：
     ```
     📌 project_profile = <未设置>（首次创建宪章，稍后由步骤 1.5 让用户选择）
     ```
     然后跳过下文第 2~4 条，直接进入"场景一/步骤 1"。
   - **已存在（场景二：修订）** → 执行 `node .xflow/scripts/xf-profile.mjs --value-only` 读取实际值，显眼打印：
     ```
     📌 project_profile = <profile>
     ```
     并继续下文第 2~4 条的方言加载逻辑。
2. 如果 `.xflow/profiles/<profile>/constitution.md` 存在，**读取该文件**并作为本次运行的行为覆写规则优先执行：
   - 指令 `终止整条命令` → 按方言固定输出打印并结束，**不执行下文任何步骤**
   - 指令 `跳过 <步骤>` → 执行到该步骤时直接跳过
   - 指令 `替换 <步骤>` → 改用方言文件中的替代内容
   - 指令 `追加 <位置>` → 在该位置附加方言文件的内容
3. 方言文件不存在或 profile 为 `general` 时，按下文通用流程执行

> 原则：本文件只维护通用逻辑；领域方言统一在 `.xflow/profiles/<profile>/` 下管理。**禁止**在本文件硬编码 `if profile == xxx` 分支——所有业务分支必须通过方言文件声明式表达。
>
> 设计权衡：理想情况下宪章只承载项目级原则约束（具体技术栈、代码路径、scaffold 流程归 `/xf/product` 方言）。**但**对于核心原则与技术方向已由行业实践固化的业务 profile（如 `xuanwu-activity` 的双端栈 + 三条核心原则），逐条追问用户徒增交互成本且信息量极低——此类 profile 允许通过方言文件提供**预置宪章模板**替代 3 轮交互式问答。本命令因此在 step 1.6 保留一个方言延迟加载点（首次创建场景下 step 1.5 完成 profile 选择后才能加载方言），用于承接此类业务 profile 的覆写。

## 场景一：首次创建（constitution.md 不存在）

### 步骤 1：项目上下文推断

自动扫描项目，收集可推断的信息（不要求用户手动提供）：

- `package.json` → 前端/后端框架、Node 版本
- `go.mod` / `pom.xml` / `requirements.txt` → 后端语言和框架
- `.eslintrc*` / `.prettierrc*` / `biome.json` → 编码规范
- `tsconfig.json` → TypeScript 配置
- `docker-compose.yml` / `Dockerfile` → 部署方式
- `README.md` → 项目描述
- `xspec/modules/` → 已有模块
- **profile 候选信号**：检测仓库根的**业务工程结构**（用于步骤 1.5 的智能推荐）：
  - 同时存在 `client/` + `lua/` 目录（**仓库根**）→ 玄武双端工程候选
  - 同时存在 `scaffold.sh` + `scaffold.bat`（**仓库根**，不是 `.xflow/tools/` 下）→ 玄武 scaffold 候选
  - **以上业务信号至少命中一条** → profile 候选记为 `xuanwu-activity`
  - 否则不做推荐（步骤 1.5 让用户自行选择）

> ⚠️ **禁止将框架自带文件作为业务信号** —— `.xflow/scripts/<dialect>/`、
> `.xflow/profiles/<dialect>/`、`.xflow/tools/scaffold.*` 这类都是 xflow 框架
> 本身分发的内容，**只要装了 xflow 就会出现**，无法判断用户业务类型。
> 新增方言时若要补充候选信号，必须**严格使用仓库根的业务工程结构**作为依据。

将推断结果作为后续问答的基础，减少用户输入量。

### 步骤 1.5：项目 profile 选择（强制询问，不可跳过）

constitution.md 的"项目配置 / `project_profile`"字段是**整个 xflow 后续命令链的行为开关**，必须由用户明确决策。即便步骤 1 推断出了候选，仍要弹选择题让用户确认（信号可能误判）。

向用户展示（遵循 CLAUDE.md 全局交互规则，**优先使用平台原生选择工具**如 Cursor 的 AskQuestion）：

```
🎯 选择项目 profile（决定 xflow 后续命令的行为分支）

推断信号：<步骤 1 检测到的业务信号摘要；若未命中则填"未检测到特定业务信号">
推荐：<命中信号时填对应 profile 名称；未命中时填"未推荐，请按项目类型选择">

| 选项 | profile           | 适用场景                                                            |
| :--- | :--------------- | :------------------------------------------------------------------ |
| A    | general           | 通用多模块 SDD 项目（后端服务、前端应用、AI Agent、系统软件等）       |
| B    | xuanwu-activity   | 玄武游戏活动工程（一仓库 = 一个活动，FGUI 客户端 + AwardLua 服务端） |
```

- 步骤 1 命中**业务信号**时：标记对应 profile 为推荐，并在"推断信号"行展示具体证据（如"检测到 client/+lua/，疑似玄武活动工程"）
- 步骤 1 未命中任何业务信号时：**不预设推荐**，让用户根据项目实际类型自行选择（这是高影响决策，宁可让用户多想 5 秒，也不要用启发式默认值把用户框死在错误 profile 上）
- **不**提供"自定义 profile"选项：选项表严格限定在 xflow 当前实际支持的 profile 内。一个没有方言文件的自定义名字除了被写进宪章外毫无行为差异，会误导用户以为"起个名字就能定制"。未来若要新增 profile（如 `web-team-x`），必须先由维护者在 `.xflow/profiles/<name>/` 下放好方言文件并同步更新本命令的选项表后才能加入——profile 的扩展走的是框架迭代路径，不是用户初始化路径

记录用户选择到内存变量 `selected_profile`，后续步骤 3 写入宪章。

### 步骤 1.6：Profile 方言延迟加载（首次创建场景专属）

场景一下 step 0 无法加载方言（彼时 profile 未定），本步承接该职责：

1. 检查 `.xflow/profiles/<selected_profile>/constitution.md` 是否存在
2. 存在 → **读取该方言文件**并按其声明的覆写动词应用到后续 step 2 / step 3 / step 4：
   - 指令 `跳过 <步骤>` → 执行到该步骤时直接跳过
   - 指令 `替换 <步骤>` → 改用方言文件中的替代内容
   - 指令 `追加 <位置>` → 在该位置附加方言文件的内容
3. 不存在 / profile 为 `general` → 按下文通用 step 2 / step 3 / step 4 流程执行

> 仅首次创建场景需要本步。场景二（修订）在 step 0 已经加载了方言，不再进入本步。

### 步骤 2：交互式问答（最多 2-3 轮）

**第 1 轮 — 项目理解**：

如果自动扫描推断到了足够信息，直接展示推断结果并请用户确认/修正。如果是新项目（没有可推断的文件），简要了解项目是什么。

本轮只需理解项目定位，不深入技术细节。

**第 2 轮 — 核心原则**：

```
接下来，你认为这个项目最重要的原则是什么？
比如：测试先行、简洁优先、安全第一、性能优先...

你可以列出 2-5 条不可妥协的原则。
```

收到回答后，将每条原则转化为**具体、可检验**的约束条件，展示给用户确认。

**第 3 轮（可选）— 补充已确定的技术方向**：

如果步骤 1 已推断出技术栈信息，展示推断结果请用户确认即可，不需要逐项提问。如果是全新项目且用户还没确定技术方向，跳过此轮——技术选型在 `/xf/product` 和 `/xf/design` 阶段确定。

**问答原则**：
- 推断能得到的信息不问用户
- 已确定的技术方向记录到宪章，未确定的不追问（留给后续阶段）
- 不问质量指标（测试覆盖率、性能阈值等）、安全实现细节、UI/API 设计规范——这些在设计阶段决定
- 给出推荐选项并说明理由
- 遵循 CLAUDE.md 全局交互规则

### 步骤 3：生成宪章

1. 读取 `.xflow/templates/_shared/constitution.md` 模板
2. 基于问答结果填充各板块
3. **将步骤 1.5 的 `selected_profile` 写入"项目配置"小节**：把模板中 `- ` + "`" + `project_profile` + "`" + `: general` 一行改为 `- ` + "`" + `project_profile` + "`" + `: <selected_profile>`
4. 替换占位符（`[PROJECT_NAME]`、`[PRINCIPLE_*]`、`[VERSION]` → `1.0.0`、日期 → 当天）
5. 未涉及的板块直接移除（不保留空板块）

### 步骤 4：确认并写入

1. 展示完整宪章内容
2. 请求确认（选项式）：
   ```
   推荐：A
   A. 确认，写入宪章（推荐）
   B. 需要调整（请指出哪些部分）
   ```
3. 确认后写入 `xspec/constitution.md`

## 场景二：修订已有宪章

### 步骤 1：加载现有宪章

读取 `xspec/constitution.md`，解析当前版本号。

### 步骤 2：理解修订意图

如用户在参数中说明了修订内容，直接分析影响范围。否则展示当前宪章并问："你想修订哪些部分？"

### 步骤 3：执行修订

1. 判断版本号变更类型：
   - **MAJOR**：核心原则被删除或根本性重新定义
   - **MINOR**：新增原则/板块，或实质性扩展现有内容
   - **PATCH**：措辞修正、格式优化、非实质性调整
2. 展示修订对比（原内容 → 新内容）
3. 建议版本号并说明理由
4. **保护 `project_profile` 字段（强制规则，所有 profile 通用）**：
   - 修订过程中**禁止**因模板重写、格式重整等原因丢失或修改"项目配置"小节中的 `project_profile` 字段
   - 若用户明确要求**切换 profile**（如从 `xuanwu-activity` 改为 `general`），必须以显著警示弹出二次确认框，列出影响面：

     ```
     ⚠️ 你正在将 project_profile 从 <current> 切换为 <target>

     影响面：
       1. 新发起的 /xf/* 命令将按 <target> 的方言（或通用流程）执行
       2. 已有 change.yaml 中的 project_profile 快照不会自动刷新
       3. 已有模块/归档不受影响，但跨 profile 的语义可能不再对齐
       4. 切换后无法自动迁移历史数据，请确认是否真的需要切换

     请确认是否继续？(yes / no)
     ```

   - 用户二次确认前**禁止**写入

### 步骤 4：确认并写入

1. 展示修订后完整宪章
2. 确认后更新文件、版本号和修订日期

## 行为规则

- 所有交互使用中文
- 推断优先于询问
- 需要用户做选择时，遵循 CLAUDE.md 全局交互规则（能自主决策的不问 + 选项式 + 推荐 + 最小化 + 优先使用平台原生选择工具）
- 核心原则必须具体、可检验、不模糊
- **不问具体技术选型细节**（用什么数据库、什么部署方式）——自动推断到的记录，没推断到的留给后续阶段
- **不问质量指标阈值**（测试覆盖率、性能阈值）——这些在设计阶段决定
- **不问设计规范**（UI 标准、API 规范、安全实现）——这些在设计阶段决定
- 修订时必须展示对比
- 宪章内容应精炼，宁少勿多
