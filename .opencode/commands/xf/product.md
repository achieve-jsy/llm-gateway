创建或修订产品定位文档，定义产品的目标用户、功能结构和产品边界。

## 用户输入

```
$ARGUMENTS
```

## 前置条件

- `xspec/constitution.md` 必须存在（不存在则提示先运行 `/xf/constitution`）

---

## 步骤 0：Profile 分支加载（始终先于其他步骤执行）

1. 执行 `node .xflow/scripts/xf-profile.mjs --value-only` 读取当前 `project_profile`
2. 显眼打印一行：`📌 project_profile = <profile>`
3. 如果 `.xflow/profiles/<profile>/product.md` 存在，**读取该文件**并作为本次运行的行为覆写规则优先执行：
   - 指令 `终止整条命令` → 按方言固定输出打印并结束，**不执行下文任何步骤**
   - 指令 `跳过 <步骤>` → 执行到该步骤时直接跳过
   - 指令 `替换 <步骤>` → 改用方言文件中的替代内容
   - 指令 `追加 <位置>` → 在该位置附加方言文件的内容
4. 方言文件不存在或 profile 为 `general` 时，按下文通用流程执行

> 原则：本文件只维护通用逻辑；领域方言统一在 `.xflow/profiles/<profile>/` 下管理。**禁止**在本文件硬编码 `if profile == xxx` 分支。

---

## 场景一：首次创建（PRODUCT.md 不存在）

### 步骤 1：收集项目信息

1. 读取 `xspec/constitution.md` 了解项目约束
2. 扫描 `xspec/modules/` 了解已有模块
3. 读取项目根目录的 README.md、package.json 等推断项目背景

### 步骤 2：苏格拉底式问答（2-3 轮）

**第 1 轮 — 产品定位**：

```
根据项目信息，我了解到这是一个 [推断的项目类型]。

请帮我理解：
1. 这个产品解决什么问题？核心价值是什么？
2. 目标用户是谁？（可以描述 1-3 个用户角色）
```

**第 2 轮 — 功能概述**：

```
基于你描述的产品定位，我初步理解产品的功能范围：

核心功能：
  - [推断的功能1]
  - [推断的功能2]

```

展示后以选项式交互确认（如：接受 / 需微调 / 重新描述）。

**第 3 轮 — 产品边界**：

```
最后确认产品边界：
1. 明确做什么？（核心功能）
2. 明确不做什么？（排除项）
```

### 步骤 3：生成产品定位文档

1. 读取 `.xflow/templates/_shared/product.md` 模板
2. 填充产品概述、目标用户、产品边界
3. 模块结构部分暂留空（由 `/xf/split` 专门定义）
4. 写入 `xspec/modules/PRODUCT.md`

### 步骤 4：确认

展示完整内容，以选项式交互请用户确认。

---

## 场景二：修订已有 PRODUCT.md

1. 读取并展示当前 `xspec/modules/PRODUCT.md`
2. 根据用户输入识别修订点
3. 更新内容，递增版本号
4. 展示修订对比，以选项式交互请用户确认

---

## 输出产物

- `xspec/modules/PRODUCT.md`

## 完成报告

```
✅ 产品定位完成

产品：<product-name>
目标用户：<user-roles>

产品定位文档：xspec/modules/PRODUCT.md

👉 下一步：执行 /xf/split 定义项目模块结构
```

## 行为规则

- 所有交互使用中文
- 推断优先于询问
- 产品边界要具体、不模糊
- 模块结构由 `/xf/split` 单独负责，此命令只关注产品定位
