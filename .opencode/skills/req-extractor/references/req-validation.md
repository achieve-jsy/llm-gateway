# req-extractor 校验与回退规则

本文档定义 `req-extractor` 在单文件生成阶段的校验项、失败回退和重试规则。

## 1. 适用范围

适用于所有 req 双模板生成任务：

- 先读取 `extract_template`
- 生成提取中间结果
- 再读取 `publish_template`
- 生成最终输出文件

本规则只负责“单文件是否允许落盘”，不负责 bundle 选择和 phase 调度。

## 2. 执行单元单文件检测

每个执行单元在写入最终文件前，必须执行两道检测。
若运行环境允许并行代理/子 Agent，执行单元必须由子 Agent 承担；
若运行环境不允许并行代理/子 Agent，则由主 Agent 串行承担对应文件的执行与检测。

### 2.1 `publish-structure-check`

检查目标：

- 最终文件必须使用 `publish_template_path` 的标题和章节结构
- 章节约束只允许来自 `publish_template_path`，不允许来自 rules/checklist 的额外硬编码章节
- 不允许直接复用 `extract_template` 的标题、章节名、提示语和检查项

判定口径：

- 先提取 `publish_template_path` 的标题层级（`#`/`##`/`###`）
- 最终文件必须覆盖模板要求的标题层级与顺序
- 若最终文件出现模板之外的“流程提示类章节”（如提取过程说明、填写指南、检查说明），判定结构失败
- 若某标题在 `publish_template_path` 中存在，则允许保留，不得按关键词一刀切误判

失败反馈建议：

- `publish-structure-check` 失败：最终文件仍包含提取模板痕迹，请严格按 `publish_template_path` 重写

### 2.2 `question-collapse-check`

检查目标：

- 扫描当前文件中的 `?（文档未说明）`
- 逐项判断该问号是否属于关键未知项白名单
- 非白名单问号不得保留

允许保留问号的前提：

- 该字段确实属于关键未知项白名单
- 当前文档和上下文无法稳定推理默认值
- 保留后不会导致实现误导

不允许保留问号的场景：

- 通用布尔开关默认值
- 开始/结束时间的缺省口径
- 非关键限制项缺省值
- 通用超时、重试、降级、一致性、幂等性策略
- 可依据同类活动或同类棋牌玩法稳定推断的常规流程和 UI 表现

失败反馈建议：

- `question-collapse-check` 失败：检测到 `{N}` 个非白名单问号，必须先收敛后再落盘

## 3. 执行单元检测失败回退

单文件检测失败时，按以下顺序处理：

1. 当前文件不得落盘为最终文件
2. 将失败原因结构化反馈给当前执行单元，不重跑整套
3. 当前执行单元只重写当前文件，并保留原提取中间结果作为输入
4. 单文件最多自动重试 `2` 次
5. 若仍失败，则将该文件标记为 `blocked`
6. 主 Agent 汇总时仅跳过或等待该文件，不影响无关文件继续执行

## 4. 主 Agent 汇总前复查

所有执行单元完成后，主 Agent 在生成 `需求提取总结报告.md` 前应再次做一次单文件结果复查：

- 若发现结构校验失败，只重跑对应文件
- 若发现非白名单问号未收敛，只重跑对应文件
- 不允许因为单文件失败而重跑整套 bundle

若本次执行因运行环境限制退化为主 Agent 串行处理，应在最终结果或报告中明确说明“本次为主 Agent 串行退化执行”。

## 5. 与报告的关系

所有默认值替换都必须进入报告汇总。

所有最终保留下来的 `?（文档未说明）` 都必须：

- 出现在最终输出文件中
- 能说明其所属的关键未知项类别
- 在报告的“未明确项汇总”中可追溯
