## 7. 风险与依赖

| 风险 / 依赖 | 影响版本 | 缓解策略 |
| :--- | :--- | :--- |
| 公司 SSO 对接周期不可控 | V0.2 | V0.1 内置本地账号回退，避免阻塞 |
| 阿里百炼 SDK 不稳定 | V0.1 | 同时准备 `voocel/litellm` 兜底通道 |
| 试点部门反馈不及预期 | V0.4 → V0.5 | 提前在 V0.3 安排 1-2 个开发者试用收集反馈 |
| Langfuse 自部署运维 | V0.6 | V0.4 末与运维 / 数据团队确认；本地 docker-compose 起步；网关只发 OTLP，后端可换 |
| 压测环境与机器 | V1.0 | V0.5 预约环境，避免临时找资源 |
| LiteLLM 替换的用户迁移成本 | V1.0+ | OpenAI 兼容协议保障 SDK 不变；Key 迁移工具提前在 V0.7 开发 |

## 8. 节奏外的灵活策略

- **同一阶段内的紧急修复** → 走 `vX.Y.Z` 的 patch 版本（如 V0.3.1），不算独立大版本
- **某阶段交付不达标** → 整体路线图右移，**不压缩功能**牺牲质量
- **临时插入需求** → 走 [`AGENTS.md`](./AGENTS.md#需求变更流程) 的需求变更流程，必须有版本归属
- **暂停的功能** → 在对应版本文档中标记 `STATUS: 推迟 → vX.Y`，并在 [`AGENTS.md`](./AGENTS.md) 的变更日志记录
