# 模型等级子预算设计（Spec v0.6）

## 背景

系统已经按公司、工作室、部门和个人建立 USD 总预算链，并在请求成功后按实际 Token 用量和模型价格累计成本。现有预算只能限制总消费，无法限制某类高价模型组在总预算中的消费规模。

本需求不新增“套餐”、积分或余额账户，而是在现有预算体系中增加可选的模型等级子预算。

## 目标

- 管理员可动态维护模型等级，并把多个模型组归入同一等级。
- 每层现有预算都可为部分模型等级配置独立 USD 上限。
- 所有调用始终受总预算约束；配置了等级子预算时，再受对应等级上限约束。
- 继续按实际路由模型的真实价格计算成本，不使用固定等级系数。
- 支持按等级查看消费、剩余预算和超限情况。

## 非目标

- 不建设计费、结算、充值或余额账户。
- 不新增独立套餐模板及套餐分配体系。

## v0.6 技术收敛

- 临时额度统一使用 `budget_temporary_overrides`，同时承载总预算和等级预算当前周期扩容。
- 下周期直接调额统一使用 `budget_limit_schedules`，不在基础额度表中堆叠计划字段。
- 调用日志增加 `budget_tier_accounting_eligible` 与 JSONB `budget_tier_constraints_snapshot`；后者保存请求实际参与等级记账的每层 scope/tier/period/Redis key/reset_at 事实，确保配置停用、删除或变更后仍可准确重建。
- 周期口径固定为系统级 `budget.timezone`（默认 `Asia/Shanghai`）和 ISO 周一周起点，由 Control Plane 与 Gateway 共享计算。
- Gateway 等级预算代码统一位于 `internal/gateway/budget`；公开 402 错误码为 `budget_exceeded` 或 `tier_budget_exceeded`。
- 功能关闭与影子期是两个状态：关闭时不累计等级计数；影子期启用累计和 would-block 计算但不执行正数额度拦截。
- 不根据价格自动划分模型等级。
- 不要求请求前预占最大可能成本，也不保证并发场景绝对不超额。
- `/v1/p/:provider/*` 直通请求不参与等级子预算。
- 不追溯等级子预算生效时间之前的消费。

## 用户与角色

- 平台管理员：维护模型等级与模型组归属，配置公司预算，并向工作室分配预算。
- 工作室管理员：查看由平台分配的工作室预算，向下配置部门预算；不得修改自身工作室总额度。
- 部门管理员：查看由工作室分配的部门预算，配置成员日常预算池、程序服务预算池和成员独立额度；不得修改自身部门总额度。
- 普通用户：查看自己预算链中可见的有效总预算、等级用量、剩余额度、限制来源和重置时间。
- Gateway：执行预算检查、成本计算、记账和超限拦截。
- Control Plane：持久化等级及子预算配置，发布配置快照，提供管理和查询 API。

## 范围

### 接口范围

覆盖已经接入现有预算与成本采集链路的模型组请求：

- OpenAI Chat Completions
- OpenAI Responses
- Anthropic Messages
- Embeddings
- Rerank
- VL Rerank

### 预算作用域

等级子预算支持现有 `BudgetAllocation` 的全部作用域，包括公司、工作室、部门和个人。个人 Key 与 Service Key 继续沿用现有预算链解析规则：

- 同一成员只允许归属一个部门。
- 同一成员的全部个人 Key 共享一份 `member` 总预算和等级额度。
- Service Key 使用所属部门 `dept_service` 程序服务预算池的等级额度，不进入成员或部门日常池。

## 核心概念

### 模型等级

- 等级由管理员动态创建，包含名称、排序和启用状态。
- 一个等级可以关联多个模型组。
- 一个模型组最多关联一个等级，也可以不关联等级。
- 模型组未关联等级时，其消费只进入总预算，不进入任何等级子预算。
- 等级被模型组或等级子预算引用时禁止删除；管理员应先解除引用。
- 模型组切换 provider 或具体模型不会改变本次请求所属等级。

### 等级子预算

- 等级子预算依附于一条现有总预算分配，不形成独立预算链。
- 日、周、月等级额度分别独立配置、检查和重置。
- 同一条总预算对同一等级、同一周期最多存在一个长期基础额度。
- 未配置：该预算层不对该等级增加额外限制。
- 配置为 `$0`：该预算层禁止使用该等级。
- 配置为正数：该预算层对该等级设置独立消费上限。
- 各等级上限之和可以大于总预算；总预算始终是最终硬上限。
- 某周期未配置时，不从其他周期自动换算额度；该周期仅受总预算及其他已配置约束。
- 子预算继承所属总预算的时区、周起始日和重置边界。
- 同一上级下允许下级额度合计超过上级额度，但管理端必须展示超配比例和风险。

示例：个人月总预算为 `$500`，高级等级上限为 `$100`。高级消费达到 `$100` 后，即使总预算仍有余额，也不能继续调用高级模型组。未配置子预算的其他等级仍可继续使用剩余总预算。

## 交互与 API 契约

### 管理能力

Control Plane 需要提供以下能力：

- 模型等级的创建、查询、修改、排序、停用和安全删除。
- 为单个或批量模型组设置、替换或清除等级。
- 查询和更新一条总预算下的等级子预算。
- 查询各预算作用域、等级、模型组的成本与剩余额度。

管理模型组时应明确展示以下状态：

- 已关联的等级。
- “未分级，仅受总预算控制”。
- 模型组内各实际模型的参考价格。

### 用户查询

用户预算查询需要在现有总预算信息之外返回：

- 可见预算链中已配置的等级子预算。
- 每个等级按日、周、月返回上限、已用、剩余、重置时间和限制来源。
- 未配置等级子预算时，不伪造无限额度数值，应明确返回“未配置”状态。
- 同时存在个人和共享预算来源时，按周期、等级分别返回真实来源，页面顶部使用“混合预算来源”。
- 有效剩余额度取全部生效约束“剩余金额”的最小值；若最小值来自上级预算，普通用户只看到状态和来源层级，不看到上级精确金额。

### 超限响应

- 沿用现有预算语义，返回 HTTP `402 Payment Required`。
- 错误码区分总预算超限和等级子预算超限。
- 等级超限响应包含首要阻断原因，以及脱敏后的其他阻断项。首要原因优先 `$0` 禁用，其次选择重置时间最晚、影响持续最久的限制。
- 权限校验先于预算检查；用户没有模型组访问权限时返回 `403`，不暴露预算状态。
- 普通用户响应不得暴露其他组织层级的预算金额或主体信息；详细超限作用域只写入管理审计日志。

## 管理后台交互设计

### 信息架构

沿用现有管理后台的侧边栏、页面标题、指标卡片、表格、弹窗和右侧抽屉样式，不新增独立“预算治理工作台”。

管理区保留以下相关入口：

- `用量看板`：分析成本、调用量和模型等级分布，不承担风险处置。
- `预算管理`：配置预算、查看预算链并处理预算风险。
- `扩容申请`：保留系统既有菜单名称；审批页按角色显示“平台扩容审批”“工作室扩容审批”或“部门额度审批”，不在预算管理中重复建设。
- `模型组授权`：继续负责访问权限，和预算限制相互独立。

平台区新增 `模型等级`，用于等级 CRUD、排序、启停和批量关联模型组。

`预算管理` 页面只保留两个页签：

- `预算总览`：预算分配、层级下钻、批量调整和配置入口。
- `风险事件`：展示并处置当前管辖范围内的预算风险，页签显示未处理数量。

不提供“变更记录”页签。单个预算详情提供对象级变更时间线；全局记录进入现有审计日志，支持按组织、成员、模型等级、操作人和时间筛选。

### 角色入口与可见范围

- 平台管理员进入预算管理时，以公司为根，查看公司指标和工作室预算表。
- 工作室管理员进入预算管理时，直接以所属工作室为根，不展示公司级页面和不可访问的上级面包屑。
- 部门管理员进入预算管理时，直接以所属部门为根，不展示工作室列表和不可访问的上级面包屑。
- 普通用户不显示管理区菜单，只通过 `我的预算` 查看个人有效预算。
- 所有列表、风险事件、筛选器和操作按钮都必须按角色管辖范围裁剪；无权限操作直接不展示，不采用点击后再报错的交互。

权限遵循“上级配置下级”的原则：

- 平台管理员配置公司自身预算，并向工作室分配。
- 工作室管理员的工作室额度只读，但可配置下属部门。
- 部门管理员的部门额度只读，但可配置部门预算池和成员独立额度。
- 成员是组织预算下钻的终点，不再展示下级分配区域。

### 预算总览与同页下钻

预算层级使用同页内容切换，不使用嵌套抽屉：

1. 公司页展示工作室预算表。
2. 点击工作室行的 `查看部门`，当前页面切换为该工作室视图。
3. 点击部门行的 `查看预算`，当前页面切换为部门视图并展示预算池和成员。
4. 点击成员行的 `预算详情`，当前页面切换为成员详情。
5. 顶部面包屑返回已访问的上级，浏览器前进和返回可恢复当前预算层级。

行名称本身不承担隐式下钻，统一使用明确的操作按钮，避免与复选框批量选择冲突。

抽屉仅用于编辑一个预算对象。任何层级最多打开一个配置抽屉，不允许抽屉内再次打开下级抽屉。配置抽屉根据对象类型展示：

- 公司：总预算和等级子预算。
- 工作室、部门：总预算、成员日常预算池、程序服务预算池和等级子预算。
- 成员：个人独立总额度和等级子预算，不展示下级预算池。

### 批量调整

公司、工作室和部门管理员可以在自己有权分配的直接下级列表中多选对象。批量调整支持：

- 设置统一固定额度。
- 按现有额度百分比增加或减少。
- 只调整指定模型等级的子预算。

提交前必须展示逐项预览，包括原值、新值、差额和父级额度校验结果。对共享池成员批量设置固定额度时，应明确提示该成员将转为个人独立额度。

### 风险事件

风险事件和预算总览属于同一 `预算管理` 菜单，通过页签切换，不新增一级侧边栏菜单。

预算总览中的风险指标、行状态和快捷入口可以跳转到 `风险事件`，并自动带入组织范围或风险类型筛选。风险列表至少展示：

- 风险类型和严重程度。
- 影响的公司、工作室、部门、预算池或成员。
- 当前额度、已用金额和使用率。
- 真正生效的限制来源。
- 发现时间和当前风险状态。

首期必须覆盖：

- 总预算达到预警阈值或已经耗尽。
- 等级子预算达到预警阈值或已经耗尽。
- 因总预算或等级子预算导致的实际请求阻断。

消费突增等异常检测可以作为后续扩展，不纳入本期验收。管理员点击 `查看预算` 时，返回预算总览并定位到具体作用域；点击 `处理` 时打开单层风险抽屉，展示完整预算链，并提供调整额度、通知负责人和查看相关用量等操作。

风险列表由实时预算用量、等级子预算和现有 80%/100% 告警记录组合生成。首期不新增“已忽略”“已关闭”等人工事件生命周期；扩容后用量重新低于阈值，或进入新预算周期时，风险按当前状态自然消失。

价格或用量缺失继续按 `$0` 记录，不生成风险事件。

### 我的预算

普通用户页面展示“有效预算”，而不是只展示个人配置值：

- 有效可用余额。
- 本月已用。
- 有效月度额度。
- 当前消费来源：个人独立额度、部门共享预算池或混合来源。
- 每个模型等级的有效额度、已用、剩余、状态和限制来源。
- 公司、工作室、部门、个人组成的当前生效预算链。

未配置个人独立额度时，页面明确说明用户正在消费部门共享池。共享池按先到先得消费，需要成员隔离时配置个人独立额度。上级任一层将某等级设置为 `$0` 时，该等级显示为不可使用，并指出限制来自哪一层，但不展示上级金额。

正在使用共享池且没有个人独立总预算的用户，不能单独申请个人等级额度；应先申请个人独立总预算。扩容入口根据真实瓶颈预填申请对象和等级，并进入现有额度审批流程。

### 审批扩容

等级额度扩容复用现有 `expansion_requests`、审批中心、审批链和批准后自动生效能力，不新增独立审批体系。

一张申请只调整一个周期的一个限制项：

- 总预算；或
- 某一个模型等级子预算。

普通用户只能申请自己的 `member` 总预算或等级额度。若真正瓶颈来自部门、工作室或公司，系统不得创建无法解除限制的个人申请，应提示“个人扩容无法解除当前限制”，并提供通知部门负责人的操作。

管理员继续按现有作用域发起申请：

- 部门管理员为部门日常池或服务池申请，由工作室负责人审批。
- 工作室管理员为工作室申请，由平台管理员审批。
- 个人申请由部门负责人审批。

申请金额表示新的目标上限。界面同时展示当前上限、当前已用、目标上限和增加金额。只允许通过审批扩容；降低额度继续使用预算配置能力。

扩容支持：

- 长期调整：修改后续周期持续使用的基础额度。
- 仅当前周期：创建临时扩容，到当前周期重置边界自动失效并恢复届时有效的长期基础额度。

同一限制项允许同时存在一张长期和一张临时待审批申请，但同类型只能有一张。临时额度与长期基础额度同时存在时，有效额度取较大值，临时扩容不能造成降额。

申请入口包括：

- “我的预算”总预算面板；
- “模型等级额度”中的具体等级；
- 预算 `402` 拦截后的引导；
- 风险事件中的额度处理入口。

系统根据入口预填预算作用域、周期、限制维度和模型等级，普通用户不选择组织层级。组织可按作用域和周期配置最大申请目标，并按用户配置每日申请次数。

申请支持普通、紧急两级优先级。紧急申请只影响排序和提醒，不跳过审批，且必须填写紧急原因并受更严格频率限制。申请原因必填，不要求附件。

审批详情必须同时展示提交时快照和当前实时值：

- 提交时上限、已用和申请目标；
- 当前上限与当前已用；
- 当前生效的上级限制；
- 批准后是否能够实际解除限制；
- 受影响的模型等级与模型组；
- 审批流水。

若审批时上级限制已变得更严格，审批人仍可批准，但必须看到“批准后仍受上级限制”的强提示；系统不得隐式修改其他预算。若当前已用已超过申请目标，则禁止批准，申请人必须修改目标后重新确认。

审批链复用现有规则：

- 个人额度：部门负责人；
- 部门日常池、服务池：工作室负责人；
- 工作室额度：平台管理员；
- 工作室负责人可按现有规则上报平台。

申请人可以修改待审批目标。提高目标后从初始审批层级重新开始；只补充原因或降低目标时重新预检但无需重启已完成层级。审批意见在批准时选填，驳回和上报时必填。

批准后自动创建或更新对应等级子预算，保留当期累计和 `effective_at`，并更新 Redis、广播配置变化。已批准申请不可撤回，回调额度通过新的配置变更完成。

批准、驳回、取消、上报和生效失败均写审批流水。站内通知和邮件默认开启，飞书/Webhook 可配置。临时扩容到期前和恢复基础额度后分别通知。长期申请默认 30 天过期且可配置；仅当前周期申请跨过重置边界时自动过期。

审批生效必须幂等。服务端按“锁定申请、重新校验、更新预算、写审批结果、发布配置变化”的顺序执行，并以申请 ID 防止重复应用。预算已持久化但 Redis 同步失败时记录同步状态，由配置对账机制恢复，不回滚已经生效的数据库配置。

审批使用动态角色池，同层任一有效负责人均可处理。负责人失权后立即移出审批池；审批池为空时通知上级管理员补充负责人，不自动改变审批层级。超过可配置 SLA 时只提醒当前审批池，不自动上报。

### 空状态

- 公司尚未向工作室分配预算时，引导先设置公司预算并开始分配。
- 工作室没有部门预算时，引导创建部门预算或等待组织同步。
- 部门没有成员独立额度时，说明成员默认继续使用部门共享池，不把该状态表现为错误。
- 未配置任何等级子预算时，明确显示“仅受总预算控制”，不展示虚构的无限额度。

### 交互补充与异常状态

扩容申请表单必须随角色和权限变化，不允许复用固定成员示例：

- 平台管理员可在公司、工作室、部门和成员等有权范围内选择申请对象。
- 工作室管理员可为所属工作室、下属部门、预算池或成员发起申请。
- 部门管理员可为所属部门、成员日常池、程序服务池或成员发起申请。
- 普通用户只显示本人，不提供组织层级选择。

表单根据入口预填总预算或模型等级、日/周/月周期、长期或仅当前周期、当前上限、当前已用和目标上限。真正瓶颈来自无权修改的上级共享池时，提交按钮改为“通知负责人”，不得创建不能解除限制的个人申请。

审批页面必须设计正常、空、加载失败、数据陈旧和“提交后预算变化”状态。提交快照与实时数据不一致时冻结批准、驳回和上报操作，先重新预检；重新预检后仍需审批人基于最新数据确认。过期、重复申请、超过最大目标或当前已用高于目标时，均在详情中给出明确原因和下一步动作。

临时额度在“我的预算”和审批详情中同时展示长期基础额度、临时增量、当前有效额度、到期时间和恢复规则。切换到日度或周度时，只显示该周期真正生效的临时额度，不把月度临时额度误展示到其他周期。

管理员直接调整预算时使用“数字输入 + 辅助比例滑块”的组合。数字输入是最终值，滑块只用于在上级可分配范围内快速调整。提交前必须填写原因并选择立即生效或下周期生效，确认页展示前后值、当前已用、影响人数和模型组、流式请求处理方式以及 `$0` 阻断风险。保存后写对象级变更时间线和全局审计。

配置界面必须并列解释：

- 未配置：不增加等级限制，仍受总预算。
- `$0`：禁止该作用域使用此等级。
- 等级停用：暂停该等级计数，历史消费仍进入报表。

模型等级有历史或引用时只允许冻结归档；无历史且无模型组、预算和审批引用时才允许删除。归档或删除均要求填写原因并展示引用影响。

“我的预算”“风险事件”“扩容申请”均展示数据更新时间，并提供空、加载失败和数据陈旧状态。数据陈旧时可展示最后一次成功数据，但必须明确其不能替代网关实时判断。移动端的审批列表转换为纵向摘要项，主要动作保持整行可点击；复杂预算表优先保留关键信息，其余字段进入详情，避免仅依赖横向滚动。

## 数据模型

### `model_tiers`

建议新增模型等级实体：

- `id`
- `name`
- `description`
- `color`
- `sort_order`
- `enabled`
- `created_at`
- `updated_at`

等级名称允许修改。历史日志保存名称快照，因此重命名不修改历史展示。

### `model_groups`

建议新增可空外键 `budget_tier_id`：

- `NULL` 表示未分级，只受总预算控制。
- 外键删除策略为 `RESTRICT`，防止删除仍被模型组引用的等级。

该字段与现有 `group_models.complexity_tier` 无关；后者用于自动路由复杂度，本字段用于预算分类。

### `budget_tier_limits`

建议新增等级子预算长期基础额度实体：

- `id`
- `budget_allocation_id`
- `model_tier_id`
- `period_type`：`daily`、`weekly`、`monthly`
- `limit_usd`
- `effective_at`
- `enabled`
- `created_at`
- `updated_at`

约束：

- `(budget_allocation_id, model_tier_id, period_type)` 唯一。
- `limit_usd >= 0`。
- 外键删除策略为 `RESTRICT`。
- 总预算仍有等级子预算时禁止删除。
- 停用、恢复或修改上限不得清除停用前当前周期已经累计的消费。

### `budget_temporary_overrides`

临时扩容与长期基础额度分开存储，并使用同一实体支持总预算与等级预算：

- `id`
- `budget_allocation_id`
- `dimension_type`：`total` 或 `tier`
- `model_tier_id`：等级临时额度必填，总预算临时额度为空
- `period_type`
- `target_limit_usd`
- `starts_at`
- `expires_at`
- `expansion_request_id`
- `status`：`active`、`expired`、`cancelled` 或 `failed`
- `created_at`
- `updated_at`

有效额度取长期基础额度与当前有效临时额度的最大值。临时扩容到期后恢复届时有效的长期基础额度，而不是申请提交时的历史快照。

### `budget_limit_schedules`

下周期生效的直接调额使用通用计划实体：

- `id`
- `budget_allocation_id`
- `dimension_type`
- `model_tier_id`
- `period_type`
- `target_limit_usd`
- `effective_at`
- `reason`
- `created_by`
- `status`：`pending`、`applied`、`replaced`、`cancelled` 或 `failed`
- `created_at`
- `updated_at`

同一预算分配、限制维度、模型等级和周期最多存在一个待生效计划。新计划经确认后把旧计划标记为 `replaced`，不得删除历史。

### `call_logs`

为保证历史口径稳定，调用日志需要保存请求开始时的等级快照：

- `budget_tier_id`，可空。
- `budget_tier_name_snapshot`，可空。
- `budget_tier_accounting_eligible`，请求开始时是否应进入等级计数器。
- `budget_tier_constraints_snapshot`，非空 JSON 数组；逐项保存实际参与等级记账的 `redis_key`、`scope_type`、`scope_id`、`tier_id`、`period_type`、`period`、`reset_at`。无适用等级约束时保存 `[]`。
- `budget_block_code`、`budget_block_dimension`、`budget_block_scope_type`、`budget_block_scope_id`、`budget_block_period_type`，预算 402 时保存首要阻断原因。

未分级模型组的等级 ID 和名称快照均为空，`budget_tier_accounting_eligible=false` 且约束快照为 `[]`。模型组之后变更等级或等级名称，不重新归类历史日志；重建不得根据当前配置猜测历史 scope 或约束。

### `budget_alert_records`

复用现有预算告警去重表承载风险事件来源，并扩展告警维度：

- `dimension_type`：`total` 或 `tier`。
- `model_tier_id`：等级告警时填写，总预算告警为空。

现有记录迁移为 `dimension_type = total`。告警去重键需要包含预算维度，保证同一预算作用域、周期和阈值下，不同模型等级可以分别产生告警。实现时应使用不受 PostgreSQL `NULL` 唯一键语义影响的确定性维度键或等价约束。

该表继续负责阈值去重，不新增人工“已忽略”“已关闭”状态。风险页面结合告警记录和实时预算用量计算当前状态。

### `expansion_requests`

复用现有扩容申请实体，建议新增：

- `dimension_type`：`total` 或 `tier`。
- `model_tier_id`：等级申请必填，总预算申请为空。
- `current_amount_snapshot`：提交时上限。
- `used_amount_snapshot`：提交时已用。
- `duration_type`：`permanent` 或 `current_period`。
- `priority`：`normal` 或 `urgent`。
- `expires_at`：申请过期时间。
- `applied_at`：实际生效时间。
- `applied_target_type`：实际更新的是基础额度或临时额度。
- `applied_target_id`：实际更新记录的 ID。
- `sync_status`：预算持久化后的配置同步状态。

`requested_amount` 继续表示批准后的目标上限。审批步骤表继续记录 `approve`、`reject`、`escalate`、`cancel` 和操作者意见。

约束：

- `dimension_type = total` 时 `model_tier_id` 必须为空。
- `dimension_type = tier` 时 `model_tier_id` 必须存在。
- 目标上限必须大于当前上限。
- 同一申请人、预算作用域、周期、限制维度、模型等级和 `duration_type` 最多存在一条待审批申请。

## 业务规则

1. 请求使用模型组在请求开始时的等级作为本次预算分类。
2. 未分级模型组只检查并累计预算链中的总预算。
3. 已分级模型组检查预算链中每层总预算，以及该层已配置的对应等级子预算。
4. 任一总预算或等级子预算已经达到上限，立即拒绝请求。
5. `$0` 等级子预算从第一次检查起即拒绝对应等级。
6. 请求成功后，同一笔实际成本同时累计到预算链各层总预算及已配置的对应等级子预算。
7. 各层预算均为独立约束，下级剩余额度不能绕过上级超限。
8. 模型组在请求执行期间变更等级，不影响已经开始的请求。
9. 修改子预算上限立即生效，且保留该子预算 `effective_at` 之后的当期累计消费；降低到已用金额以下时，后续请求立即被拒绝。
10. 首次创建子预算时从 `effective_at` 开始统计，不回填本周期更早的消费。
11. 删除后重建不得作为重置当期消费的手段；存在当期消费的配置应停用而不是物理删除。
12. 模型组换等级后，历史消费保留在原等级，新请求从变更生效后进入新等级。
13. 进行中的流式请求达到上限时不中断，完成后记账并阻断后续请求。
14. 等级子预算停用期间继续写调用日志和报表，但不进入额度累计；恢复后继续使用停用前累计。
15. 功能开关关闭期间继续记录等级快照和报表消费，但不进入等级额度计数器；重新启用后继续使用关闭前累计。

## 成本计算

- 成本单位固定为 USD。
- 数据库与 API 使用 6 位小数定点 Decimal，单次请求按 `ROUND_HALF_UP` 形成记账快照。
- Redis Lua 使用整数微美元累计，禁止直接使用浮点美元比较。
- 使用最终实际路由模型的价格快照计算成本。
- Chat、Responses、Messages 和 Embeddings 按输入、输出、缓存读取、缓存写入等价格桶计算。
- Rerank 优先按 `search_units` 及其单价计算。
- 使用 Catalog 或模型自定义价格的现有优先级，不为等级设置价格系数或兜底价格。
- 价格缺失时按 `$0` 记账，不产生缺价告警。
- 上游未返回有效用量时按 `$0` 记账。
- 最终 HTTP 状态码小于 `400` 才记账；失败请求及内部失败重试不单独累计成本。

## 状态变化

### 模型等级

- 启用：可被模型组和新子预算引用。
- 停用：保留历史引用和报表，不允许新增引用。
- 归档：已有调用、审批或审计历史的等级只能归档，不出现在新建配置中。
- 删除：仅在从未被引用且没有历史数据时允许。

### 等级子预算

- 未配置：只应用总预算。
- 启用且为零：禁止对应等级。
- 启用且为正数：应用独立等级上限。
- 停用：停止等级限制并暂停额度累计，保留配置和停用前当期用量；报表仍记录实际消费。
- 恢复：继续使用原 `effective_at` 和停用前当期累计用量。

## 执行流程

1. 鉴权并解析现有预算链。
2. 从请求模型组解析等级快照；模型组不存在或无等级时不创建等级上下文。
3. 执行现有总预算检查。
4. 对预算链每一层查询当前等级子预算；未配置或停用则跳过，已配置则检查累计消费。
5. 任一检查失败时返回 `402`，不调用上游。
6. 调度实际 provider/model 并执行请求。
7. UsageCollector 根据最终用量和实际模型价格计算成本。
8. 成功请求把成本原子累加到各层总预算和适用的等级子预算。
9. 写入包含等级快照与价格快照的调用日志。
10. 异步执行等级预算 80% 和 100% 阈值评估。

## 错误处理

- Redis 不可用或预算脚本执行失败时，正数额度沿用现有 fail-open；`$0` 属于静态禁用并保持 fail-closed。
- fail-open 请求不执行对应 Redis 预算累计，避免只记账未检查的不一致状态；调用日志仍正常写入。
- Control Plane 配置快照暂时不可用时继续使用 Gateway 最近一次成功加载的快照。
- 价格或用量缺失按 `$0`，不阻断请求且不产生告警。
- 等级配置被引用时，删除 API 返回冲突错误。

## 安全与权限

- 等级和等级子预算的写操作沿用现有预算管理权限。
- 普通用户只能读取与自己预算链相关的汇总结果。
- 所有直接调额必须填写原因并记录变更前后值；降低到已用金额以下时强制二次确认。
- 有直接配置权时直接修改，无配置权但有申请权时走审批。
- 预算配置变更、审批、等级变更、停用、归档、删除、导出和紧急解除操作写入审计日志。
- 等级预算不替代模型组授权；用户必须先通过现有模型组访问控制。

## 可观测性

需要增加：

- 按等级统计成本、请求数、模型组分布和预算利用率。
- 等级子预算拒绝次数，并按等级和预算作用域聚合。
- Redis fail-open 次数。
- 等级配置变更审计。
- 默认 80%/100% 阈值，允许按模型等级覆盖预警阈值。
- 告警只在越过阈值时发送；降回阈值以下后再次越过才重新告警。
- 扩容、成本冲正或用量纠错后重新评估风险。

不对价格缺失或用量缺失新增告警。

## 性能与可靠性

- Gateway 不直连 PostgreSQL；等级及子预算配置通过现有快照机制下发。
- 预算检查与累计使用 Redis Lua，保证单次操作内的多 key 一致性。
- 延续“请求前检查累计额、成功后累计真实成本”模式，并发请求可能造成小幅超额。
- 等级检查不增加新的外部同步调用。
- 报表以 `call_logs` 的等级和价格快照为事实来源；Redis 用量用于实时拦截。
- Redis 当前周期数据丢失时，总预算按调用日志作用域重建，等级预算严格按调用日志的 scope constraint JSONB 快照重建；不使用当前配置反推历史。重建采用短时全局 lease：新可计费请求返回 `503 budget_rebuild_in_progress`，已放行请求通过带 heartbeat 的 inflight ZSET 完成结算；inflight 归零且 call-log Stream 可靠 drain 到 PostgreSQL 后才分页构建新 generation，最终以单个 active-generation 指针原子切换。lease 丢失或任一步失败均保持旧指针；旧 generation 保留用于回滚和 TTL 自然过期。
- 实时用量不可用时，页面展示最近成功数据、更新时间和“数据可能延迟”，不把调用日志临时估算伪装成实时值。

## 兼容与迁移

- 新增字段和表采用 Expand 阶段迁移，不修改现有预算字段语义。
- 存量模型组的等级为空，继续只受总预算控制。
- 存量预算不自动创建等级子预算。
- 功能上线前的调用日志不回填等级。
- 首次创建等级子预算时以 `effective_at` 为统计起点。
- 新旧 Gateway 蓝绿共存期间保持等级拦截关闭。全部 Gateway 升级到支持版本后，先运行至少一个完整预算周期的影子计算并完成对账，再统一开启。
- 设置两个独立开关：正数等级额度拦截开关，以及 `$0` 静态禁用开关。普通降级只关闭正数额度；严重故障时才单独关闭 `$0` 禁用。
- 实施时必须通过 GORM model 修改和 Atlas diff 生成迁移，迁移文件与 `atlas.sum` 一起校验；不得手工修改 `atlas.sum`。

## 生命周期与运营规则

### 组织与人员变化

- 成员转部门后立即切换到新部门预算链；历史留在原部门，原部门待审批申请自动取消。
- 部门转工作室后立即切换到新工作室预算链；历史保留，原审批链待处理申请自动取消。
- 工作室或部门停用后停止新调用和新申请，冻结配置、取消待审批申请并保留历史。
- 成员停用或离职后立即禁用 Key、冻结个人预算、取消待审批申请并保留历史。
- 成员重新启用时，预算配置保持冻结，由管理员确认后恢复；旧 Key 不自动恢复。
- 同周期重新启用保留停用前累计，不得借此重置额度。

### 配置变更

- 管理员直接调额支持立即生效或下个周期生效。
- 同一额度已有待生效变更时，新变更经二次确认后替换旧变更；审计保留被替换记录。
- 历史配置回滚视为一条新的配置变更，只恢复额度值，不回滚或清空累计用量。
- `$0` 紧急解除允许有直接配置权的管理员立即执行，但必须填写原因并完整审计。
- 降额或设置 `$0` 前展示预计影响人数和模型组。

### 通知策略

- 个人额度变更通过站内信和邮件通知本人。
- 部门共享池变更通知部门负责人；受影响成员收到站内提示，默认不群发邮件。
- 工作室或公司变更通知对应负责人和管理员，普通用户通过站内公告或调用阻断提示获知。
- 飞书和 Webhook 作为可配置通知渠道。

### 数据、报表与审计

- 未分级模型组统一进入“未分级”虚拟分类，只受总预算且不可配置子预算。
- 子预算周期中途首次生效时，页面分别展示“本周期总消费”和“生效后计入额度的消费”。
- 用量补记或纠错同步调整当前周期总预算和等级累计，写审计并重新评估风险。
- 上游退款或人工冲正写独立负向调整，恢复可用额度并保留完整审计。
- 管理员可以按权限范围导出等级预算、风险和审批 CSV/XLSX；导出行为写审计。
- 审批流水、等级快照和预算审计在线保留三年，之后进入归档策略。

### 批量与告警

- 批量调额或审批预览标记失败项，只提交校验通过的对象，并逐项返回结果。
- 扩容后使用率降回阈值以下会重新武装告警；再次越过阈值时产生同周期新一轮风险。
- 风险持续高于阈值时不重复发送，避免告警轰炸。

## 验收标准

1. 管理员可以动态创建等级，并把多个模型组关联到同一等级。
2. 模型组可以保持未分级，调用时只消耗总预算。
3. 任一现有预算作用域可以只为部分等级配置子预算。
4. 未配置子预算时不增加等级限制；配置 `$0` 时对应等级请求返回 `402`。
5. 已分级请求的实际成本同时计入所有适用层级的总预算和等级子预算。
6. 未分级请求的实际成本只计入总预算。
7. 总预算或任一适用等级子预算耗尽时，请求在上游调用前被拒绝。
8. 等级上限修改后立即依据 `effective_at` 以来的累计消费判断是否超额。
9. 首次启用不统计 `effective_at` 之前的消费。
10. 模型组或等级名称变更不改变历史调用日志中的等级快照。
11. Chat、Responses、Messages、Embedding、Rerank 和 VL Rerank 使用一致的等级预算语义。
12. 价格或用量缺失时请求正常完成并按 `$0` 记账。
13. Redis 不可用时正数额度 fail-open 并记录指标，`$0` 静态禁用仍然阻断。
14. 等级被模型组或子预算引用时无法删除。
15. 用户可以查看自己的等级上限、已用、剩余和重置时间，管理员可以查看组织级按等级报表。
16. 平台、工作室、部门管理员分别从公司、所属工作室、所属部门进入预算管理，且只能查看和操作管辖范围。
17. 公司、工作室、部门和成员通过同页内容切换和面包屑下钻，不出现嵌套抽屉。
18. 有分配权限的管理员可以对直接下级执行固定额度、百分比和等级子预算批量调整，并在提交前查看校验预览。
19. 预算管理只包含“预算总览”和“风险事件”两个页签；扩容申请继续使用现有独立菜单。
20. 风险事件支持从风险定位预算作用域，并通过单层抽屉查看预算链和执行处置。
21. 普通用户可以区分个人独立额度和部门共享池，并查看每个等级真正生效的限制来源。
22. 一张扩容申请只能调整总预算或一个模型等级额度，申请金额表示新的目标上限。
23. 普通用户只能申请个人额度；上级预算是实际瓶颈时不创建无效个人申请。
24. 模型等级扩容复用现有个人、部门、工作室和平台审批链。
25. 审批详情同时展示提交快照、实时用量、上级限制和批准后的实际效果预检。
26. 批准后自动更新对应总预算或等级子预算，保留当期累计并幂等生效。
27. 批准、驳回、取消、上报和生效失败均写入审批流水并发送通知。
28. Redis 同步失败不回滚已持久化预算，配置对账可以恢复同步。
29. 日、周、月等级额度可分别配置和检查，未配置周期不自动换算。
30. 临时扩容与长期基础额度分离，到期恢复届时有效基础额度。
31. 混合预算来源按周期和等级分别展示，上级金额对普通用户脱敏。
32. 子预算停用或功能开关关闭期间的消费进入报表但不进入额度累计。
33. `$0` 静态禁用在 Redis 故障和普通额度降级期间保持 fail-closed。
34. 组织、成员和审批人变化按生命周期规则冻结、取消或重新授权。
35. Redis 用量可以从调用日志及生效区间重建。
36. 正式拦截前完成全量 Gateway 升级和完整周期影子对账。
37. 扩容申请表单按平台、工作室、部门和普通用户裁剪可选对象，不出现越权组织或固定成员数据。
38. 上级共享池是实际瓶颈时，普通用户只能通知负责人，不创建无效个人扩容申请。
39. 审批详情在提交快照与实时数据不一致时冻结决策并要求重新预检。
40. 临时额度明确展示基础值、增量、当前有效值、到期时间和恢复规则。
41. 直接调额要求原因和生效时间，提交前展示影响确认并记录前后值审计。
42. 未配置、`$0` 和等级停用在配置界面具有不同文案、状态和确认行为。
43. 我的预算、风险事件和扩容申请均提供空、失败和数据陈旧状态。
44. 移动端审批采用摘要布局，核心流程无需依赖横向表格滚动。

## 已确认决策

- 使用真实价格，不使用等级乘数。
- 不新增套餐体系，扩展现有预算。
- 等级动态维护，模型组可不分级。
- 等级子预算可选且为独立上限。
- 支持全部现有预算作用域。
- 采用事后真实成本记账，接受并发小幅超额。
- 价格和用量缺失均按 `$0`，不告警。
- 等级额度支持日、周、月独立限制，继承总预算时区和重置边界。
- 未配置周期不自动换算，不增加额外等级限制。
- 修改上限时保留生效后的历史用量。
- 历史日志保存等级快照。
- 正数额度在 Redis 故障时 fail-open，`$0` 静态禁用保持 fail-closed。
- 复用现有失败请求、告警、权限和 HTTP `402` 语义。
- 存量数据保持兼容，不回填上线前等级消费。
- 预算层级采用同页下钻和面包屑返回，不使用嵌套抽屉。
- 抽屉只用于单对象配置或单风险处置。
- 预算管理只保留“预算总览”和“风险事件”，不新增“变更记录”页签。
- 保留现有“扩容申请”菜单名称，不改名为“额度审批”；审批页标题按角色变化。
- 平台、工作室、部门管理员分别以公司、所属工作室、所属部门为管理根节点。
- 等级额度扩容复用现有扩容申请和审批中心，不新增独立审批流。
- 一张申请只调整一个限制项，普通用户只申请个人额度。
- 申请金额表示目标上限，批准后自动、幂等生效。
- 审批必须展示提交快照、实时状态、上级限制和实际效果预检。
- 审批扩容需求和方案纳入本规格，具体开发可作为独立实施阶段排期。
- 扩容支持长期和仅当前周期两种类型；一张申请只调整一个周期、一个限制项。
- 同一限制项允许临时与长期申请并存，同类型只允许一张待审批申请。
- 有直接配置权时直接调整，无配置权时走审批；全部直接调额必须填写原因。
- 审批使用动态角色池，SLA 超时只提醒、不自动上报。
- 站内信和邮件默认开启，飞书/Webhook 可配置。
- 共享池先到先得；需要成员隔离时配置个人独立预算。
- 同一成员只属于一个部门，全部个人 Key 共享成员预算；Service Key 使用部门服务池。
- 下级额度允许超配上级，但必须展示超配风险。
- 金额使用 6 位小数 Decimal，Redis 使用整数微美元。
- 功能关闭和子预算停用期间继续报表记录，但暂停等级额度累计。
- 有历史的模型等级只能归档，无历史且无引用时才允许删除。
- 变更记录采用对象级时间线和全局审计，不恢复预算管理页签。
- 审批、等级快照和预算审计在线保留三年。

## 假设

- 所有纳入范围的请求都能在调用开始时稳定识别请求模型组。
- 现有预算链是公司、工作室、部门和个人预算作用域的唯一来源。
- Catalog 和模型自定义价格仍是成本计算的唯一价格来源。
