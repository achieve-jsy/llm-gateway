# 上下文语义分析 · 完整设计方案（主线定稿）

> 一条主线走完：从一个用户一周的全部会话 → 到最终「定性 / 疑似 / 待核查」结论。
> 收拢前面所有讨论结论：GLM5.3-flash 量化版(512K)、口径 A(大模型只作证据)、会话压缩四态、3.6 待核查红线、成本可控。
> 覆盖的情况：3.2 挤牙膏、3.3 多任务不切会话、3.5 杀鸡用牛刀(可选)、3.6 与工作无关(待核查)。
> 不覆盖：3.1 前缀污染、3.4 输出失控(纯数值，不需语义)。
> 本文是执行主线；细节口径引用 context-analysis / session-content-v2 / anomaly-work-unrelated / over-model 四份分设计。

---

## 0. 全局判断（先定基调）

1. **语义分析不产指标，只产“一个证据信号”**。所有指标(成本/占比/轮次/命中率/归因费用)都由数值算，语义只回答一个问题：「内容/主题上，X 成立吗?」
2. **口径 A**：语义证据 + 确定性元数据，双条件同时成立才升「定性」；语义单独 → 保持「疑似」。3.6 特殊：双条件也只到「待核查」。
3. **能不读正文就不读，能不上大模型就不上**。语义分析是**最后一公里**，前面全靠元数据把范围榨到最小。
4. **512K 是安全垫不是省事理由**：判主题只需「每轮用户意图」，不塞全文。
5. **默认关，可降级**：语义层关闭时全部回落元数据「疑似」，系统照常可用。

## 2. 阶段一 · 选取（决定“哪些会话要做语义分析”，全程免费不读正文）

### 2.1 为什么先选取
一周几万条会话，绝不能每条都读正文送模型。**原则：能改变结论的才做语义分析。** 四道筛。

### 2.2 筛①：元数据先给每个会话定状态

用会话切分 + 元数据判定(context-analysis)，给每个会话打状态：

| 状态 | 含义 | 进不进语义分析 |
| --- | --- | --- |
| 正常 | 五类都没命中 | ❌ 做了也不会变问题 |
| 已定性 | 前缀污染(3.1)/输出失控(3.4)绝对口径够了 | ❌ 已能定性，不值 |
| 疑似 | 元数据命中，但缺语义证据 | 进筛② |

### 2.3 筛②：只留“语义能帮上忙”的类型

| 情况 | 元数据独立能定性? | 语义要判什么 | 进不进 |
| --- | --- | --- | --- |
| 3.1 前缀污染 | 能(500k/30%) | — | ❌ |
| 3.4 输出失控 | 能(分位) | — | ❌ |
| 3.2 挤牙膏 | 判不了「同一件事」 | same_task? | ✅ |
| 3.3 多任务不切会话 | 判不了「任务在切」 | task_switch? | ✅ |
| 3.5 杀鸡用牛刀 | 数值能出疑似 | simple_task?(可选,默认不做) | ⚠️ |
| 3.6 与工作无关 | 时间窗能出待核查 | work_related? | ✅(只排优先级) |

### 2.4 筛③：按会话费用排序，只做值得的
- 候选会话按**会话费用降序**；
- 取 **Top N(默认20)** 或 **累计覆盖该人80%疑似费用**，二者取小；
- **费用地板**：低于「该人总成本1% 或 绝对¥5」(取大)的，直接不做，保持疑似。

### 2.5 筛④：缓存
- key = `sha256(session_id + 意图序列 + prompt_version + model_version)`；命中取历史信号。

> 四筛后：~300 会话 → ~5 待判 → 缓存命中后实际调用 ~2 次。

## 3. 阶段二 · 取证（对待判会话读正文，处理“很大/累积/压缩”）

### 3.1 事实：内容累积，但会被压缩
- 正常会话内容累积：末轮 prompt 含全部历史 → 读末轮一条即可还原全程。
- 但会话可能压缩/截断，末轮不含全部、也不一定最全。四态：累积 / 摘要替换 / 滑动窗口截断 / 分段压缩。

### 3.2 压缩检测(免费，用 prompt_seq，不读正文)

```text
compacted = false; 压缩点 = []
for i in 1..len(prompt_seq)-1:
    if prompt_seq[i] < prompt_seq[i-1] * 0.7:   # 明显下降沿(阈值可配)
        compacted = true; 压缩点.append(i)
if max(prompt_seq) 不在末轮: compacted = true
(有采集时) reset_flag[i]=true 也是压缩点
```

### 3.3 分段选读(决定读哪几条正文)

| compacted | 读哪条 | 条数 |
| --- | --- | --- |
| false | 末轮 | 1 |
| true | 每个上升段的末轮 | 段数(通常2-3) |

例 `8k→20k→45k→[压缩]→9k→30k→[压缩]→12k` → 读第3、6、7轮，不逐轮、不只读最后一条。
正文从 `call_traces` 取(archive_status 0/1直读 PG，2从jsonl.gz回读)。

### 3.4 抽“用户意图序列”(把大正文压到百字级)

```text
对每条读到的 request_body(messages 数组):
  1. 过滤 role='user'，按序
  2. 剥离上下文数据: 去掉 ```代码块```/超长引用(>500字)/base64/日志/大JSON
  3. 每条 user 取: 开头一句 + 结尾一句(意图在头、追问在尾)
  4. 拼成意图序列(压缩会话跨段拼接)
  5. 脱敏: 去邮箱/手机/身份证/APIKey/URL token
```
结果:送模型内容 = 用户指令浓缩，**与会话体积无关**。末轮600k全是代码 → 意图序列可能200字。

### 3.5 取不到证据就降级(守 v0.6 不误判)
以下 → `uncertain` → 保持疑似:
- 正文读不到(log_enabled=false/回读失败)
- 检测到摘要占位(assistant含「以上是之前总结」等，或意图序列明显缺轮)
- 跨压缩边界判不了(只在能读原文的段内判)
- 意图序列抽空(全数据无自然语言)

## 4. 阶段三 · 判断(GLM5.3-flash 量化，512K)

### 4.1 一个统一分类器，四种问题共用

送模型的都是「意图序列」，只是**问的问题不同**(由调用方指定 task)：

| 情况 | 问模型 | 期望信号 |
| --- | --- | --- |
| 3.2 挤牙膏 | 全程是不是同一件事? | same_task |
| 3.3 多任务不切会话 | 任务有没有切换? | task_switch(+switch_turns) |
| 3.5 杀鸡用牛刀 | 这任务简单还是复杂? | simple_task/complex_task |
| 3.6 与工作无关 | 内容像工作还是私事? | work_related/not_work_related |

### 4.2 输入(紧凑，非全文)
```json
{"session_id":"conv-123","compacted":true,"question":"task_switch",
 "intent_seq":[
   {"i":1,"seg":1,"user_head":"帮我把函数改成异步的"},
   {"i":2,"seg":1,"user_head":"写一下它的单测"},
   {"i":5,"seg":2,"user_head":"查下明天上海天气"}],
 "gap_between_seg":true}
```

### 4.3 输出契约(结构化，量化模型防乱编)
```json
{"signal":"task_switch","switch_turns":[5],"confidence":0.82,"reason_tag":"code_to_weather"}
```
- 强制 JSON；低温度、限 max_tokens、拒非JSON。
- 置信阈值：3.2/3.3/3.5 用 0.6；**3.6 用 0.7(更保守)**。
- 不达标/超时/gap无法跨段判 → `uncertain`。
- 只取结构化字段，不接受自由文本当依据。

### 4.4 一会话一次调用
512K 装单会话意图序列，不塞多会话(避免串味、缓存粒度粗、审计难)。

## 5. 阶段四 · 合成(口径 A，四种情况区别对待)

### 5.1 3.2/3.3/3.5：语义 + 元数据双条件 → 可升定性

| 情况 | 元数据条件 | 语义信号 | 合成 |
| --- | --- | --- | --- |
| 3.2 | 轮次≥8 且 短输入占比高 | same_task | 都成立→**定性**；uncertain→疑似 |
| 3.3 | 超长 且 命中不差 且 无reset | task_switch | 都成立→**定性**；uncertain→疑似 |
| 3.5 | 输入短/输出不长/单轮 且 高阶 | simple_task | 都成立→**定性**；uncertain→疑似 |

### 5.2 3.6：语义只排“待核查优先级”，永不定性/定罪(红线)

| 时间窗(层1) | 语义(层2) | 结论 | 核查优先级 |
| --- | --- | --- | --- |
| 命中>20% | not_work_related | **待核查** | 高 |
| 命中>20% | uncertain/未读到 | **待核查** | 中 |
| 命中>20% | work_related | **待核查** | 低(提示「像工作，疑似加班误报」) |
| 未命中 | 任何 | 不进3.6 | — |

3.6 无论如何**只到待核查，由负责人终裁，可申诉**。语义单独(时间窗未命中)永不进。

### 5.3 通用规则
- 语义信号**永不单独定性**(口径A)。
- 升 verdict **不改归因费用**(金额已由数值算定，只改定性/疑似标签)。
- `inferred` 会话(无真实session_id)：即使语义支持，仍封顶疑似(会话边界不可靠)。

## 6. 缓存 · 审计 · 成本(贯穿四阶段)

- **缓存**：内容不变永远只判一次(阶段一筛④)。
- **审计**：每次判断记 `{session_id, question, model, model_version, prompt_version, signal, confidence, ts, caller}`。
- **成本控制**：只判「疑似+缺语义类型+费用够高+无缓存」；每人TopN封顶+全局周预算封顶；轻量量化模型+意图序列(非全文)。
- **成本估算**：单次input几百~上千token；每人~2-5次/周；500人~1000-2500次/周；flash量化 → 小额可控。
- **透明**：报告附注「本期语义判断覆盖X会话，消耗约¥Y」。

---

## 7. 合规(读正文的前置)
- 突破「不解析正文」红线，上线前过合规评审。
- 脱敏(§3.4)、最小化(只发意图序列)、不落正文副本。
- 3.6 更严：结果只对直属负责人+本人可见，层2单独开关。
- 总开关默认关，关闭全部回落元数据疑似。

---

## 8. 边界与降级汇总(全部保持疑似/待核查，不误判)

| 场景 | 处理 |
| --- | --- |
| 正文读不到 | uncertain→疑似 |
| 会话被摘要压缩，早期意图丢 | uncertain→疑似 |
| 跨压缩边界判不了 | 段内判，跨段uncertain→疑似 |
| 意图序列抽空 | uncertain→疑似 |
| 模型非JSON/超时/低置信 | uncertain→疑似 |
| 超每人/全局上限 | 保持疑似，注记未覆盖 |
| inferred会话 | 封顶疑似 |
| 3.6 无论语义如何 | 封顶待核查，人终裁 |
| 总开关关闭 | 全部回落元数据疑似 |

## 9. 落地顺序(主线)

| 阶段 | 步 | 内容 | 依赖 | 读正文/大模型 |
| --- | --- | --- | --- | --- |

| 取证 | 3 | 压缩检测(prompt_seq下降沿) | 会话切分 | ❌ |
| 取证 | 4 | 分段选读+正文读取器(call_traces三态) | 归档读器 | ✅读 |
| 取证 | 5 | 意图序列抽取(剥大数据+头尾句+脱敏) | 步4 | ✅读 |
