# 杀鸡用牛刀 3.5 · 判定与（可选）语义判断设计

> 目的：落 v0.6 §3.5「简单任务走贵模型，三块费用一起被单价放大」。
> 定位：五种情况里**最不依赖大模型**的一个——数值代理已能出「疑似」，语义只是把「像不像简单任务」从代理判断升级为定性。本文重点说清**值不值得为它上大模型**，给「不上」和「上」两套，默认「不上（数值代理 + 疑似）」。
> 前提沿用：GLM5.3-flash 量化版、口径 A、可关闭。
> 现有数据（已核）：`model_tiers`（档位）+ `model_catalog`（价格）+ `CachedInputPerMtok/InputPerMtok/OutputPerMtok` 均可取。

---

## 0. 一句话结论（先给判断）

- **数值代理（输入短/输出不长/一轮结束 + 走高阶模型）已能判「疑似」**，且能算出溢价——**这一层必做，不用大模型**。
- **是否升级为「定性」要不要读内容判「任务真的简单吗」——可选**。它的边际价值最低（3.5 的动作是「换个便宜模型」，疑似就足以提示），成本却和 3.2/3.3 一样，所以**默认不上大模型**，缺场景标签就停在「疑似」。
- 若确实要上，用**已有的 task_kind/场景标签**优先，实在没有再考虑读内容——顺序见 §4。

---

## 1. v0.6 §3.5 原文拆解

- **看**：是否像简单任务（输入短、输出不长、一轮结束）、是否高阶模型、相对轻量模型的溢价（有模型目录才能算）。
- **如何分析**：规模上像简单任务 **且** 走了高阶模型。指标：疑似简单请求中高阶次数占比。**无场景标签时只标疑似。**
- **排除**：长上下文、高轮次、复杂任务用高阶，合理。
- **钱落在**：三块乘贵单价（选型是单价放大器）。

注意 v0.6 自己就写了「无场景标签时只标疑似」——**它本来就允许停在疑似**，不强制读内容。这是「默认不上大模型」的依据。

---

## 2. 层1 · 数值代理判定（必做，不用大模型）

### 2.1 判定（两个条件同时成立）

```text
条件A「规模像简单任务」（纯数值，三者都满足）:
  - 输入短:   prompt_tokens < 同岗位 P25（或绝对阈值兜底，如 < 2000）
  - 输出不长: completion_tokens < 同岗位 P50
  - 一轮结束: 该请求所在会话 turns == 1
条件B「走高阶模型」:
  - model 的 tier ∈ {high, ultra}（来自 model_tiers）

命中 = A 且 B
排除 = 长上下文 / 高轮次(turns>1) / 复杂任务（A 任一不满足即排除）
```

### 2.2 溢价（归因费用，用 model_catalog 价格算）

```text
premium = 实际成本 − 用轻量替代模型重算的成本
其中「轻量替代」= 同能力组内最低档位模型（model_tiers 排序取 tier=low/economy）
重算成本 = prompt_uncached × light.InputPerMtok
        + cached          × light.CachedInputPerMtok
        + completion      × light.OutputPerMtok   （单位 /1M）
若无轻量替代（组内只有高阶）→ premium 不可算 → 标 [数据不足]，不计溢价
```

### 2.3 层1 产出指标

| 指标 | 口径 |
| --- | --- |
| hit_count | 疑似简单请求中走高阶的次数 |
| share | 疑似简单请求中高阶次数 ÷ 疑似简单请求数（v0.6 指标） |
| attributed_cost | Σ premium（相对轻量模型的溢价，非整笔费用） |
| evidence | {prompt, completion, turns, model, tier, light_alt} |
| verdict | **suspected**（缺「任务真简单」的语义确认） / not_computed（无轻量替代算不了溢价） |

> 层1 单独就产出「疑似」。v0.6 允许到此为止。

---

## 3. 为什么默认不上大模型（成本/价值权衡）

| 维度 | 3.5 情况 |
| --- | --- |
| 边际价值 | 低。3.5 的动作是「简单任务换便宜模型」，「疑似」提示已足够让人去看；升到「定性」对动作几乎无增益 |
| 误判代价 | 低。不像 3.6 指向个人不当，3.5 最多是「建议换模型」，判错影响小 |
| 大模型成本 | 与 3.2/3.3 同量级（读内容判复杂度），但收益远低 |
| 已有替代 | task_kind/场景标签（元数据）已能近似判「任务类型」，不必读正文 |

**结论：性价比不划算，默认停在层1「疑似」。** 只有当用户明确要「3.5 也要定性」且愿付成本时，才上层2。

---

## 4. 层2 · （可选）语义判定——三级来源，能不读正文就不读

要把 3.5 从疑似升定性，判据是「这任务是不是真简单」。按**成本/侵入性从低到高**取证据，能满足就停：

### 4.1 优先级 1：task_kind / 场景标签（元数据，免费，不读正文）
- 若已采集 `task_kind` 或客户端带 `scene` 标签 → 直接判：
  - `scene ∈ {简单问答, 翻译, 格式化, 单元测试…}` → simple → 与层1双条件成立 → **confirmed**
- 有标签就到此为止，**不读正文、不上大模型**。

### 4.2 优先级 2：GLM5.3-flash 判任务复杂度（读内容，仅当无标签且用户要求定性）
- 只对「层1 已命中、且无 task_kind、且费用够高」的请求读内容（复用 session-content §3 抽意图指纹）。
- prompt：判 `simple_task / complex_task / uncertain`（同 v2 §4.2 的分类器，复用）。
- 输出 simple_task 且层1成立 → confirmed；uncertain → 保持 suspected。

### 4.3 优先级 3：不判
- 无标签、用户不要求定性、或超成本上限 → 保持层1「疑似」。

> 关键：**大模型是 3.5 的最后手段，不是默认路径**。task_kind 能覆盖大部分，读内容是兜底。

---

## 5. 合成（口径 A，与 3.2/3.3 同）

| 层1 数值 | 语义证据（标签或大模型） | verdict |
| --- | --- | --- |
| 命中 | simple_task | **confirmed** |
| 命中 | uncertain / 无 | **suspected** |
| 未命中 | 任何 | not_hit |

语义单独不成立命中；升 verdict 不改 attributed_cost（溢价金额不变，只改标签）。

## 6. 报告呈现

**杀鸡用牛刀** · `[疑似]`（或 `[已定性]` / `[数据不足]`）
- 疑似简单请求中高阶占 X% · 归因费用（溢价）¥Y
- 证据：输入 A（<同岗P25）/ 输出 B（<P50）/ 单轮 / 走高阶模型 M
- 轻量替代：同组 model L，估算溢价 ¥Y（无替代则「无轻量替代，溢价不可算」）
- 👉 建议：简单任务可降至 L / 轻量档

---

## 7. 落地顺序

| 步 | 内容 | 依赖 | 用大模型 |
| --- | --- | --- | --- |
| D1 | 层1 数值代理判定（输入短/输出不长/单轮 + 高阶） | model_tiers、分位基线 | ❌ |
| D2 | 溢价算法（轻量替代重算 + 无替代降级） | model_catalog 价格 | ❌ |
| D3 | 优先级1：task_kind/场景标签升定性 | 采集 task_kind（可选） | ❌ |
| D4 | 优先级2：GLM5.3-flash 判复杂度（可选，兜底） | session-content 分类器 + 合规 | ✅ |

> D1/D2 必做且免费，产出「疑似 + 溢价」。D3 有标签就升定性。D4 是最后兜底，默认不做。

## 8. 对 v0.6 §3.5 的守约校验

| v0.6 §3.5 | 落点 |
| --- | --- |
| 看：像简单任务/是否高阶/相对轻量溢价 | 层1 条件A + 条件B + §2.2 溢价 |
| 判定：规模像简单 且 走高阶 | §2.1 条件 A 且 B |
| 指标：疑似简单请求中高阶次数占比 | §2.3 share |
| 无场景标签时只标疑似 | §2.3 verdict=suspected（默认停这） |
| 排除：长上下文/高轮次/复杂用高阶 | §2.1 排除 |
| 钱落在三块乘贵单价 | 溢价=相对轻量模型的三块差额 |
| 有模型目录才能算溢价 | §2.2 无轻量替代 → not_computed |

> 与其他语义类的区别：3.5 是唯一「默认不上大模型」的——数值代理够用、边际价值最低、v0.6 明确允许停在疑似。大模型是可选兜底，且优先用 task_kind 标签而非读正文。
