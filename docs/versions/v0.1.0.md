## 1. 版本主题

> **跑通端到端**：起一个 Go 服务，通过 OpenAI 兼容协议把请求转发到至少 1 个真实厂商。

## 2. 目标

- 落地技术架构（[`../01-TECH-STACK.md`](../01-TECH-STACK.md)）中的最小可运行子集
- 验证「OpenAI 兼容协议」+「Provider 适配层」抽象的合理性
- 为后续所有版本提供可叠加的工程基线（CI、配置、测试、Docker 部署）
- 回扣 PRD 核心价值：④ 极简接入（雏形）

## 3. 范围（in-scope）

- [ ] Go 项目骨架（cmd / internal / pkg / migrations / deploy 目录）
- [ ] Gin 框架 + 中间件框架（logger / recover / request-id）
- [ ] Provider 适配层接口设计（`internal/adapter/`）
- [ ] **至少 2 个厂商接入**：阿里百炼 + DeepSeek（走 OpenAI 兼容路径）
- [ ] OpenAI 兼容路由：`POST /v1/chat/completions`（同步 + 流式 SSE）
- [ ] 配置体系：Viper + `.env` + `config.yaml` 分层
- [ ] Postgres / Redis 通过 `docker-compose.dev.yml` 一键拉起（**不引入 ClickHouse**）
- [ ] **OTLP exporter 接入骨架**（OpenTelemetry Go SDK），开发环境默认指向本地 stdout collector；可选拉起 Langfuse 容器作为实测后端
- [ ] 数据库 schema 版本化基础（golang-migrate）
- [ ] 基础健康检查 `/healthz` `/readyz`
- [ ] Swagger 文档自动生成（swaggo/swag）
- [ ] 单元测试框架 + 1 个示例测试
- [ ] GitLab CI 基础流水线（lint + test + build）

## 4. out-of-scope（明确不做）

- ❌ SSO 登录（V0.2）
- ❌ Key 管理（V0.2，本版本用硬编码测试 token）
- ❌ 模型组 / 负载均衡（V0.3，本版本一个模型直连一个厂商）
- ❌ 限流 / 用量统计（V0.4）
- ❌ 前端管理后台（V0.2）
- ❌ AWS Bedrock（V0.2）

## 6. 验收标准

- [ ] `make dev` 一键启动所有依赖 + 网关服务
- [ ] 用 `openai` Python / Node SDK 配置 `base_url=http://localhost:8080/v1`，能成功调通百炼和 DeepSeek 的至少 1 个模型
- [ ] 流式请求（`stream=true`）正确返回 SSE 数据块
- [ ] 单元测试覆盖率 ≥ 50%（核心 adapter 与 router 必覆盖）
- [ ] CI 流水线绿灯
- [ ] `/healthz` 200，`/readyz` 检查 DB / Redis 连通性
- [ ] OTLP 出口可关闭（环境变量），关闭时不影响业务请求；开启时 stdout collector 能看到至少 1 个完整调用 trace
- [ ] 拉取项目后，新人按 README 能在 30 分钟内跑起来
