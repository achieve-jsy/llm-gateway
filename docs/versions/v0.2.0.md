## 1. 版本主题

> **员工自助**：员工用公司账号登录平台，自己创建 Key、调用模型，所有调用与员工身份绑定。

## 2. 目标

- 让 V0.1 的能力可被真实员工使用，而不是开发者硬编码 token
- 完成「身份 → Key → 调用追溯」的最小闭环
- 提供首版管理后台（Vue 3 + Element Plus）
- 回扣 PRD 核心价值：① 安全自助 Key 分发（基础部分）｜ ④ 极简接入（动态模型列表）

## 3. 范围（in-scope）

### 后端

- [ ] 公司 SSO（OIDC）对接，登录拿到 SSO 用户信息后写入 `users` 表
- [ ] 内部 JWT 签发（管理后台使用）
- [ ] Key CRUD：
  - 创建（自动生成 `sk-` 前缀的密钥，仅创建时明文返回一次）
  - 列表（脱敏展示）
  - 禁用 / 启用 / 删除
- [ ] Key 与 `user_id` 强绑定，调用时鉴权链路：`API Key → User → 部门`
- [ ] 调用时把 `user_id` / `key_id` / `dept_id` 写入请求上下文，为后续日志、限流铺路
- [ ] **专属查询接口** `GET /v1/me/models`：基于 SSO 身份返回当前用户可用的模型列表

### 前端（首版管理后台）

- [ ] Vue 3 + Vite + Element Plus + Pinia + Vue Router 基础骨架
- [ ] OIDC 登录回调页 + 登录态管理
- [ ] 我的 Key 页面：创建 / 查看 / 禁用 / 删除
- [ ] 模型列表页面（来自 `/v1/me/models`）
- [ ] 首页：欢迎 + 简单使用文档（curl + openai SDK 示例）

### 部署

- [ ] 前后端镜像分离，`docker-compose.yml` 拉起 gateway + web + nginx

## 4. out-of-scope（明确不做）

- ❌ 模型组（V0.3，本版本一个 model 一行配置）
- ❌ 限流（V0.4）
- ❌ 用量统计（V0.4）
- ❌ 部门权限（V0.5）
- ❌ Key 设备监控（V0.7）
- ❌ 复杂的角色权限（本版本只区分 admin / user 两个角色）

## 6. 验收标准

- [ ] 真实员工用公司账号能登录管理后台
- [ ] 员工能自助创建至少 1 个 Key，并用该 Key 调通百炼 / DeepSeek / Bedrock 任一模型
- [ ] 调用日志里能查到 `user_id` 与 `key_id`（即使日志只打到 stdout）
- [ ] `/v1/me/models` 返回的模型列表与配置中 enabled 的模型一致
- [ ] Key 明文只在创建时返回一次，列表页只显示后 4 位
- [ ] 禁用 Key 后立刻不可调用（毫秒级生效）
