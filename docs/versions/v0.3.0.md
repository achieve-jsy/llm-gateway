## 1. 版本主题

> **业务解耦 + 高可用**：业务方不再直接绑定具体模型，调用「模型组」即可，组内多个渠道自动负载均衡 + 故障切换。

## 2. 目标

- 实现 PRD 核心价值 ⑥ 的基础：「模型分层封装」（按智力等级低 / 中 / 高）
- 实现 PRD 核心价值 ③ 的基础：单一厂商故障不影响业务
- 让管理员能在后台动态切换模型组的底层模型，业务方无感

## 3. 范围（in-scope）

### 后端

- [ ] `model_groups` / `model_group_members` 表 + 迁移
- [ ] 模型组路由规则：
  - 按 `weight` 加权随机
  - 按 `priority` 顺序回退（主 → 备）
  - 简单健康检查（30s 探活，5xx / 超时累计触发熔断）
- [ ] 故障切换：当前选中渠道连续失败 N 次（可配）→ 切换到下一渠道
- [ ] `/v1/chat/completions` 的 `model` 字段可以是模型组名（如 `default`、`reasoning`、`fast`）
- [ ] 调用结束后更新渠道健康度：Redis 滑动窗口（30s）记录成功 / 失败 / 延迟，供路由决策实时消费；同时通过 OTLP span 属性带出，归档由 V0.6 接入 Langfuse 后承接
- [ ] OpenAI 兼容路由：`POST /v1/embeddings`（用于后续语义缓存的铺垫）

### 前端

- [ ] 模型组管理页面（管理员）：
  - 创建 / 编辑模型组（id、名称、显示名、智力等级）
  - 添加 / 移除组员（厂商 + 模型 + 权重 + 优先级）
- [ ] 模型组的「试调用」面板（方便管理员快速验证）
- [ ] 在「模型列表页」展示模型组（区分于具体模型）

## 6. 验收标准

- [ ] 业务方用 `model="default"` 调用，请求被路由到组内任意一个具体模型
- [ ] 手动停掉某个厂商，30s 内自动切到组内备份渠道，业务无感
- [ ] 管理员在后台增加 / 移除模型组成员后，新请求立即生效（不需要重启）
- [ ] 至少 3 个模型组示例：`default`（默认）、`reasoning`（高智力）、`fast`（快速）
- [ ] Redis 渠道健康度滑动窗口可查询（每次调用后秒级更新），路由器能基于该数据做决策
