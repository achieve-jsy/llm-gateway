## 1. 版本主题

> **防滥用 + 见数据**：上线 TPM / RPM / 并发限流；用量按日聚合写入 Postgres（明细 Trace 在 V0.6 走 OTLP → Langfuse），员工和管理员都能在前端看到自己的用量。

## 2. 目标

- 实现 PRD 核心价值 ① 的限流部分（防脚本滥用）
- 实现 PRD 核心价值 ② 的基础（个人 / 部门 / 模型多维用量统计）
- 实现 PRD 核心价值 ⑦ 的主体（Token 套餐 + 配额）
- 本版本完成后**进入 MVP 阶段**，可邀请试点部门使用

## 3. 范围（in-scope）

### 后端 — 限流

- [ ] Redis Lua 脚本实现原子 TPM / RPM / 并发计数
- [ ] 限流维度（可叠加配置）：
  - 按 Key（默认必有）
  - 按模型 / 模型组
  - 按部门
- [ ] 触发限流时返回 429 + 标准 `X-RateLimit-*` 响应头
- [ ] 管理后台配置限流阈值（持久化到 `quotas` 表）

### 后端 — 用量统计

> **设计原则**：调用明细全部走 OTLP → Langfuse（在 V0.6 完整落地），本版本只在网关内做**用量聚合**写入 Postgres，给前端用量页 / 限额检查使用，不依赖 Langfuse 也能跑。

- [ ] 调用完成时同步累加进程内的「用量 buffer」（按 `user_id × dept_id × model_group × model × date` 分桶）
- [ ] 异步 flusher：每 60s（可配）把 buffer 数据 **upsert** 到 Postgres `usage_daily` 表
- [ ] `usage_daily` 字段：`date / user_id / dept_id / model_group / model / requests / tokens_in / tokens_out / cost_estimate`
- [ ] 当日实时累计兜底：同时写一份 Redis `usage:buf:{date}:{user_id}:{model}`，flusher 故障时前端仍能从 Redis 看到当日近似值
- [ ] 成本估算配置：每个模型的 input / output 价格表（`models.pricing`）
- [ ] OTLP span 上同步打上 `tokens_in / tokens_out / cost / cached` 属性（为 V0.6 Langfuse 接入做铺垫）

### 后端 — Token 套餐（基础版）

- [ ] `token_plans` 表：日 / 周 / 月配额（按模型组分桶）
- [ ] 调用前 quota check：`已用 + 本次预估 > 配额` → 拒绝（或限流）
- [ ] 默认套餐：所有员工初始一个「通用套餐」，避免上线后立刻全员被卡

### 前端

- [ ] 个人用量页：今日 / 本周 / 本月 Token 使用进度 + 调用次数 + 估算成本
- [ ] 部门用量页（管理员）：部门维度排行 + 趋势
- [ ] 模型维度用量页（管理员）
- [ ] 限流配置页（管理员）
- [ ] 套餐配置页（管理员）

## 6. 验收标准

- [ ] 设置某 Key 的 RPM=10，连续发 20 次请求，第 11 次起返回 429
- [ ] 设置某 Key 的并发=2，并发发 5 次，3 次被拒
- [ ] 调用完成后 ≤ 60s 内 Postgres `usage_daily` 能查到聚合数据；Redis 当日累计是秒级更新
- [ ] 个人用量页能正确显示日 / 周 / 月 Token 数（精确到分钟更新）
- [ ] 模型价格调整后，新调用的成本估算立即生效
- [ ] 默认套餐对所有员工生效，不会出现「上线即全部 403」
