## 1. 版本主题

> **谁能调什么**：按部门 / 角色精细化分配模型组使用权限，与限额管控联动，实现「权限 + 用量」双重管控。

## 2. 目标

- 完善 PRD 核心价值 ⑥：业务解耦 + 权限管控
- 解决「无关部门使用高成本模型」的问题
- 让动态模型列表（`/v1/me/models`）按权限过滤，业务方只能看到自己能调的

## 3. 范围（in-scope）

### 后端

- [ ] `roles` `user_roles` 表（基础 RBAC）：admin / user / dept_admin
- [ ] `permission_model_groups` 表：可被分配的「权限组」（如 `dept_a_models`、`internal_high_intel`）
- [ ] `dept_model_group_permissions` 表：部门 ↔ 权限模型组 ↔ 模型组的多对多关系
- [ ] 权限决策：调用时检查 `User.Dept → 部门拥有的权限组 → 是否包含本次目标模型组`
- [ ] `/v1/me/models` 按权限过滤返回结果
- [ ] 限额管控扩展：限额可绑定到「部门 + 模型组」维度（与 V0.4 的套餐机制叠加）
- [ ] 审计：权限变更必须留痕（`permission_audit_logs`）

### 前端

- [ ] 部门管理页（管理员）：CRUD 部门（如未从 SSO 同步则手动维护）
- [ ] 权限模型组管理页（管理员）：组装哪些模型组归为一个权限组
- [ ] 部门权限分配页（管理员）：给某部门勾选可用权限组
- [ ] 用户角色管理页（管理员）：分配 admin / dept_admin
- [ ] 「我的模型」页根据权限过滤，权限受限时显示「需联系 dept_admin」提示

## 4. out-of-scope（明确不做）

- ❌ 项目维度的权限（V1.x）
- ❌ 权限审批流（V1.x）
- ❌ 临时权限授予 / 到期（V1.x）

## 6. 验收标准

- [ ] 给「部门 A」配置仅可用 `default` 模型组，部门 A 员工调用 `reasoning` 模型组被 403 拒绝
- [ ] 同一员工换部门后，立即看到的模型列表自动变化
- [ ] 管理员页面能完整完成「创建权限组 → 给部门分配 → 给用户分配角色」全流程
- [ ] 权限变更后 `permission_audit_logs` 有记录（who / when / what）
- [ ] 限额可配置为「部门 A 的 reasoning 模型组日 1M Token」并按该维度统计 / 拦截

## 7. 依赖与风险

| 项 | 类型 | 说明 | 缓解 |
| :--- | :--- | :--- | :--- |
| 部门数据源 | 依赖 | 是否能从 SSO / HR 系统同步 | 若不行，本版本提供手动维护页面 |
| 权限模型理解成本 | 风险 | 用户可能搞混「模型组」「权限模型组」「部门权限」 | 文档 + 前端引导 + tooltip |
