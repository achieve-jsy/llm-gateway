## 1. 版本主题

> **安全闭环 + 智能路由 + 性能调优**：Key 设备监控 + 异常自动告警；负载策略升级为多决策；最后一公里的性能优化，为 GA 做准备。

## 2. 目标

- 完整落地 PRD 核心价值 ① 的安全部分：「设备监控 + 异常告警」
- 升级 PRD 核心价值 ③：从「单纯故障切换」升级为「多决策动态路由」
- 在 GA 前完成性能优化，让 V1.0 的压测能达到目标

## 3. 范围（in-scope）

### 后端 — 设备监控 + 告警

- [ ] `api_key_devices` 表：每次新设备调用时记录
  - 设备指纹（IP + User-Agent + 简易客户端类型推断）
  - 首次使用时间 / 最近使用时间 / 调用次数
- [ ] 异常检测规则（V1 简单规则版，复杂智能放 V1.x）：
  - 同一 Key 短时间内 > N 个新设备 → 异常
  - 同一 Key 出现地理位置异常（IP 跨区域突变） → 异常
  - 单 Key 突发 RPM 暴涨 → 异常
- [ ] 异常事件 → 飞书 / 钉钉 / 邮件 webhook 通知（可配置）
- [ ] 自动响应：异常 Key 自动限流或临时禁用（可配置）

### 后端 — 多决策负载策略

- [ ] 综合评分函数 = w1·健康度 + w2·延迟 P95 + w3·报错率 + w4·权重
- [ ] 评分排序后按 Top-N 加权随机
- [ ] 配置项：
  - 评分权重
  - 延迟阈值触发降权
  - 报错率阈值触发熔断（V0.3 是简单熔断，本版本可配阈值与窗口）
- [ ] 路由决策可追踪：日志中记录「为什么选这个 provider」

### 后端 — 性能优化

- [ ] 流式响应零拷贝 / 减少 GC 压力（buffer pool）
- [ ] **OTLP exporter 调优**：批量发送大小 / 间隔 / 队列容量；动态采样（高 QPS 时按比例采样，低 QPS 时全采）
- [ ] 用量 flusher 调优：合并写入、Postgres `INSERT ... ON CONFLICT` 批量 upsert
- [ ] Postgres 查询慢日志分析 + 关键索引补齐
- [ ] HTTP client 连接池调优（厂商连接复用）

### 前端

- [ ] Key 设备列表页：每个 Key 的当前活跃设备
- [ ] 异常事件列表页：所有触发过的异常 + 处置状态
- [ ] 告警渠道配置页（管理员）：webhook URL / 告警阈值
- [ ] 路由策略配置页（管理员）：权重调整 / 阈值配置

## 6. 验收标准

- [ ] 用一个 Key 在两台不同机器调用，Key 详情页能看到两个设备
- [ ] 模拟「5 分钟内 5 个新设备」触发告警，飞书 / 钉钉收到通知
- [ ] 模拟「单 Key RPM 暴涨」触发自动限流，业务被 429 拦截
- [ ] 多决策路由：人为提升某厂商延迟 → 该厂商被路由权重下降，可在日志看到决策依据
- [ ] 网关额外延迟 P95 ≤ 20ms（不含上游）
- [ ] 单实例压测 ≥ 1000 QPS（纯转发，mock 上游）
- [ ] 异常事件页有完整的处置闭环（标记已查看 / 已处理）
