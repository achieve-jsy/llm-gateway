## 2. 目标

## 3. 范围（in-scope）

### 验证 / 压测

- [ ] 单实例压测：
  - 纯转发（mock 上游） ≥ 1000 QPS
  - 真实上游 ≥ 500 QPS（不被上游限速制约）
  - 端到端延迟 P95 / P99 数据收集
- [ ] 故障演练：
  - 主要厂商宕机 → 故障切换是否生效
  - Redis 宕机 → 限流降级行为是否合理（fail-open or fail-closed 明确）
  - **OTLP collector / Langfuse 不可达** → 业务请求不受影响；本地 buffer 兜底；恢复后补发
  - Postgres `usage_daily` flusher 故障 → Redis 当日累计兜底；恢复后重对账
- [ ] 长时间稳定性：连续运行 72h 内存 / 文件句柄无泄漏
- [ ] 多并发 Key 验证：100 个并发 Key 同时调用不互相影响

### 安全审计

- [ ] Key 存储是否加密 / 哈希（数据库脱库后不可直接利用）
- [ ] OWASP Top 10 自查（SQL 注入 / XSS / 越权）
- [ ] 调用日志脱敏策略评审
- [ ] 限流绕过尝试（同一 IP 多 Key 切换、突发流量）
- [ ] 公司安全团队评审（提前预约）

### LiteLLM 替换方案

- [ ] 用户迁移指南：从 LiteLLM Key 切换到模型网关 Key 的步骤
- [ ] 业务方迁移指南：`base_url` / `model` 字段映射对照表
- [ ] 平滑切流方案：DNS / 负载均衡灰度比例切换
- [ ] 双跑监控期：模型网关与 LiteLLM 并行运行，对比指标
- [ ] 回滚预案：发现重大问题时如何快速回滚

## 6. 验收标准（北极星指标）

| 指标 | 目标 | 验证方式 |
| :--- | :--- | :--- |
| **接入用户数** | ≥ LiteLLM 现有 100 人 | 后台统计 |
| **日均请求数** | ≥ LiteLLM 当前日均量 | 双跑期对比 |
| **接口健康可用率 SLA** | ≥ 99.9% | 灰度期 1 周统计 |
| **TTFT P95** | 较 LiteLLM 下降 ≥ 30% | A/B 同模型对比 |

| 报错率 | ≤ 0.5% | 灰度期统计 |

| 故障演练 | 全部用例通过 | 演练记录 |
