# 测试任务 01: 登录、侧边栏菜单与路由守卫

## 设计目标

验证新交互架构下：
1. 四个账号均可正常登录
2. 侧边栏菜单按角色**精准显隐**
3. 路由守卫按角色**正确拦截**
4. 关键原则：**入口不藏**（manager 角色直接看到「模型组授权」菜单，无需进入「模型组」页面才能找到授权入口）

## 关键交互预期（对照表）

| 角色 | 可见菜单 | 不可见菜单 |
|------|---------|----------|
| normal_user | 我的 Key / 模型广场 / 模型组健康 | 模型组授权 / 组织架构 / 渠道管理 / 模型管理 / 角色管理 / 系统设置 等 |
| studio_admin_b | 我的 Key / 模型广场 / 模型组健康 / **🆕 模型组授权** / 组织架构（我的范围） | 渠道管理 / 模型管理 / 角色管理 / 系统设置 |
| dept_admin_a | 我的 Key / 模型广场 / 模型组健康 / **🆕 模型组授权** / 组织架构（我的范围） | 渠道管理 / 模型管理 / 角色管理 / 系统设置 |
| admin | 全部菜单 | - |

2. 导航到 `http://localhost:8090/login`

## 验收标准

| # | 检查项 | 通过条件 |
|---|--------|---------|
| 1 | 4 账号登录均成功 | URL 不再是 `/login`，侧边栏出现 |
| 2 | admin 菜单完整 | 15+ 菜单项全部可见 |
| 3 | normal_user 菜单最简 | 仅基础菜单，无管理入口 |
| 4 | 「模型组授权」独立菜单 | studio/dept admin 侧边栏直接可见此菜单 |
| 5 | normal_user 路由守卫 | `/admin/entitlements` → 403 |
| 6 | manager 路由放行 | studio/dept admin 都能访问 `/admin/entitlements` |
| 7 | admin 专属路由 | studio/dept admin 访问 `/admin/groups`、`/admin/org/roles` 等均 → 403 |
| 8 | 视图差异 | studio/dept admin 看到的 `/admin/entitlements` 与 admin 不同（入口少、信息少） |
| 9 | 信息不泄露 | studio/dept admin 在 `/admin/entitlements` 看不到超出自己管辖范围的卡片 |
