# 测试任务 02: Admin 在授权管理页切换开放模式

## 设计目标

验证 admin 在 `/admin/entitlements` 页面通过**卡片视图**直观地识别、切换模型组的开放模式（公开 / 受控）。

核心要点：
1. **卡片顶部用状态色块**区分 公开（🟢绿）vs 受控（🟠橙），一眼可见
2. **切换操作直接放在卡片内**（不是藏在行尾或弹窗里），有 popconfirm 兜底
3. **其他角色看到的卡片只读**，不可切换

## 前置条件

- 使用 `admin` 登录
- 系统中至少存在：
  - 1 个 public 公共组（如 `deepseek-chat`）
  - 1 个 controlled 受控组（如 `claude-opus`）

---

## 测试 2.1: admin 进入授权管理页，看到卡片视图

**步骤**:
1. admin 登录
2. 导航到 `/admin/entitlements`（或点击侧边栏「模型组授权」）
3. 等待页面加载

**预期结果**:
- 页面标题「模型组授权」
- 卡片网格布局呈现
- 每张卡片包含：
  - 模型组名称（大字号）
  - 顶部状态色块标签（🟢 公开 / 🟠 受控）
  - 统计数字（X 工作室授权 / Y 部门开通）或「全员可用」字样
  - 操作按钮（切换开放模式 / 管理授权）

---

## 测试 2.2: 公开组卡片外观

**步骤**: 定位到一张 `open_mode='public'` 的卡片（如 deepseek-chat）

**预期结果**:
- 卡片顶部有 🟢 绿色 status pill，文字为「公开」
- 卡片 body 区域显示「全员可用」字样
- 卡片 footer 区域按钮文案为「切换为受控」（或图标按钮 + tooltip）

---

## 测试 2.3: 受控组卡片外观

**步骤**: 定位到一张 `open_mode='controlled'` 的卡片（如 claude-opus）

**预期结果**:
- 卡片顶部有 🟠 橙色 status pill，文字为「受控」
- 卡片 body 显示授权统计：「🏢 N 工作室授权」「🏬 M 部门开通」
- 卡片 footer 有「切换为公开」按钮 + 「管理授权 →」按钮

---

## 测试 2.4: 点击「切换为受控」按钮弹出确认气泡

**步骤**:
1. 在 public 组（如 deepseek-chat）卡片上，点击「切换为受控」按钮
2. 等待 popconfirm 出现

**预期结果**:
- Popconfirm 气泡出现在按钮旁
- 标题文案：**「切换为受控？切换后需逐工作室/部门授权」**
- 气泡包含两个按钮：「确定」（primary）和「取消」（default）

---

## 测试 2.5: 取消切换

**步骤**: popconfirm 出现后，点击「取消」

**预期结果**:
- 气泡消失
- 卡片保持原状（仍为 🟢 公开）
- 无 message 提示

---

## 测试 2.6: 确认切换「公开」→「受控」

**步骤**: 在 popconfirm 中点击「确定」

**预期结果**:
- ✅ 顶部弹出成功 message：「已设为受控」
- ✅ 卡片顶部色块从 🟢 绿 pill 变为 🟠 橙 pill
- ✅ 卡片文字从「全员可用」变为「0 工作室授权」「0 部门开通」（或保持为 0）
- ✅ 卡片 footer 按钮文案从「切换为受控」变为「切换为公开」
- ✅ 卡片新增「管理授权 →」入口

---

## 测试 2.7: 点击「切换为公开」按钮弹出确认气泡

**步骤**: 在受控组卡片上点击「切换为公开」按钮

**预期结果**:
- Popconfirm 出现
- 标题文案：**「切换为公开？全公司自动可用」**
- 有「确定」和「取消」两个按钮

---

## 测试 2.8: 确认切换「受控」→「公开」

**步骤**: 点击 popconfirm 中的「确定」

**预期结果**:
- ✅ 成功 message：「已设为公开」
- ✅ 卡片色块从 🟠 橙 → 🟢 绿
- ✅ 卡片 body 文案变为「全员可用」
- ✅ 卡片 footer 按钮回到「切换为受控」
- ✅ 「管理授权 →」入口消失（公共组不需要管理授权）

---

## 测试 2.9: 其他角色（studio/dept admin）的卡片为只读

**步骤**:
1. 使用 `studio_admin_b` 登录
2. 导航到 `/admin/entitlements`
3. 定位到任一受控组卡片

**预期结果**:
- 卡片顶部色块仍正确显示 🟢 或 🟠
- **卡片 footer 不显示**「切换为受控」「切换为公开」按钮
- 若点击卡片任意可点区域，不弹出任何 popconfirm
- 卡片只有「开通部门 →」或「管理部门开通 →」（工作室范围操作）

---

## 测试 2.10: dept_admin 视角同样只读

**步骤**: 使用 `dept_admin_a` 登录 `/admin/entitlements`

**预期结果**:
- 卡片无「切换为公开/受控」按钮
- 只能看到「已可用」区和「可开通」区的区分，但不可切换开放模式

---

## 测试 2.11: 切换失败的错误处理

**前置**: 通过 DevTools 拦截 API 让切换失败，或构造特殊状态

**步骤**:
1. 在 public 组卡片点击「切换为受控」
2. 点击确认
3. API 返回 4xx/5xx

**预期结果**:
- 顶部出现红色 error message：「切换失败」或具体错误信息
- 卡片**保持原状**不变
- 可以再次尝试切换
- 控制台无未捕获异常

---

## 测试 2.12: 筛选器辅助查看

**步骤**:
1. admin 在 `/admin/entitlements` 顶部筛选区域
2. 点击「开放模式」下拉框
3. 选择「受控」

**预期结果**:
- 卡片网格刷新为只显示受控组卡片
- 所有卡片均为 🟠 橙 pill

再选择「公开」：
- 卡片刷新为只显示公开组

选择「全部」：
- 全部卡片恢复显示

---

## 关键 DOM 选择器提示

- 卡片容器: `.entitlement-card` 或自定义组件
- 状态色块: `.status-pill.status-pill--public` / `.status-pill--controlled`
- 色块内文字: `公开` / `受控`
- 统计数字: `.entitlement-card__stats` 下多个 `.stat-item`
- 切换按钮: `button[data-action="toggle-open-mode"]` 或文案包含「切换为受控」「切换为公开」
- 管理授权入口: `button[data-action="manage-entitlements"]` 或文案包含「管理授权」
- 筛选器: `.entitlement-page__filters` 内的 el-select

## 验收标准

| # | 检查项 | 通过条件 |
|---|--------|---------|
| 1 | 色块一目了然 | 绿色 pill=公开，橙色 pill=受控 |
| 2 | 切换操作直接放在卡片内 | 不藏弹窗、不藏表格尾按钮 |
| 3 | 双向切换均可 | public → controlled、controlled → public |
| 4 | 有 popconfirm 兜底 | 避免误触 |
| 5 | 切换后卡片即时刷新 | 色块/文案/按钮全部联动 |
| 6 | 其他角色只读 | 没有切换按钮 |
| 7 | 筛选器可用 | 按开放模式过滤卡片 |
