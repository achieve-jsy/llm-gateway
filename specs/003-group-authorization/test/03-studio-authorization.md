# 测试任务 03: Admin 授权/撤销工作室

## 设计目标

验证 admin 在 `/admin/entitlements` 的受控组卡片中，通过「管理授权 →」入口进入**抽屉抽屉式管理面板**，完成工作室级授权的全流程。

设计要点：
1. **入口清晰**：受控组卡片上有「管理授权 →」按钮，点击右侧滑出 720px 抽屉
2. **抽屉内两个 Tab**：工作室授权（admin only）+ 部门开通（admin / studio_admin / dept_admin 可见，内容不同）
3. **授权动作有节奏感**：添加用 Dialog，撤销用 popconfirm（带级联文案警告）
4. **信息隔离**：studio_admin 进入抽屉后**看不到**工作室授权 Tab

## 前置条件

- 使用 `admin` 登录
- 系统中至少有一个 `controlled` 受控组（如 `claude-opus`）
- 至少存在 2 个工作室，其中 studio_admin_b 所属工作室是其中之一

## 测试 3.14: studio_admin 进入抽屉时看不到工作室授权 Tab

**步骤**:
1. 登出 admin，使用 `studio_admin_b` 登录
2. 导航到 `/admin/entitlements`
3. 点击本工作室已获授权的受控组卡片上「开通部门 →」或「管理部门开通 →」按钮（文案以实际为准）
4. 等待抽屉打开

**预期结果**:
- ✅ 抽屉打开成功
- ✅ 抽屉内**只显示**「部门开通」一个 Tab
- ✅ 「工作室授权」Tab **不可见**（不是灰色禁用，而是直接不渲染）
- ✅ 抽屉 title 同 admin 视角

> 此为**信息最小暴露原则**的关键验证：studio_admin 不应看到 admin 授权给哪些工作室，也不应有机会去管理这个列表。

## 关键 DOM 选择器提示

- 卡片管理授权按钮: `button[data-action="manage-entitlements"]` 或文案含「管理授权」
- 抽屉: `.el-drawer`，标题在 `.el-drawer__header`
- Tab 切换: `.el-tabs__item`（label="工作室授权" / label="部门开通"）
- 「+ 授权工作室」按钮: `button` 文字含「授权工作室」
- 子 Dialog: `.el-dialog` 标题含「授权工作室」
- 子 Dialog 内 select: `.el-select`（filterable）
- 子 Dialog「确定授权」按钮: 按钮文字="确定授权" type=primary
- 每行「撤销」按钮: 表格行中 type=danger 的 button，文字="撤销"
- Popconfirm: `.el-popconfirm` 内 `.el-button--danger` 文字="确定撤销"
- Success message: `.el-message--success` 文字="已授权工作室" 或 "已撤销工作室授权"

## 验收标准

| # | 检查项 | 通过条件 |
|---|--------|---------|
| 1 | 入口明显 | 受控组卡片上有「管理授权 →」按钮 |
| 2 | 抽屉信息完整 | 标题、两个 Tab、表格、操作按钮齐备 |
| 3 | 授权流程闭环 | 选择 → 确定 → 新增行 → 卡片统计 +1 |
| 4 | 撤销有警告 | popconfirm 文案强调「下属部门同时失效」 |
| 5 | 撤销级联可见 | 撤销后卡片统计数联动减少 |
| 6 | studio_admin 视图隔离 | 抽屉中无「工作室授权」Tab |
| 7 | dept_admin 视图隔离 | 同上 |
| 8 | 重复授权已防止 | 已授权工作室在下拉中 disabled 或不可见 |
