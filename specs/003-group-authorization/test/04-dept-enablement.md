# 测试任务 04: 三视角的部门开通 / 撤销

## 设计目标

验证 admin / studio_admin / dept_admin 三种角色都能为部门开通受控组权限，但**操作入口、操作范围、视图**完全不同。

| 角色 | 入口 | 范围 | 视图特点 |
|------|------|------|----------|
| admin | 抽屉「部门开通」Tab | 任何工作室下的任何部门 | 工作室筛选器可选任意已授权工作室 |
| studio_admin | `/admin/entitlements` 卡片「管理部门开通 →」按钮 或 抽屉的「部门开通」Tab | 仅自己工作室下的部门 | 工作室筛选器锁定为本工作室 |
| dept_admin | `/admin/entitlements` 页面「可开通」区卡片的「开通本部门 →」按钮 | 仅自己部门 | 双列布局：已可用 / 可开通 |

## 前置条件

- 系统中至少有：
  - 受控组 `claude-opus`（已授权给 studio_admin_b 所属工作室）
  - 受控组 `gpt-4`（未授权给任何工作室）
  - public 组 `deepseek-chat`
- studio_admin_b 所属工作室下有至少 2 个部门（dept_admin_a 所属部门是其中之一）

---

### 第一部分：admin 在抽屉内开通部门（4.1 - 4.10）

#### 测试 4.1: 进入部门开通 Tab

**步骤**:
1. admin 登录 → `/admin/entitlements`
2. 点击某受控组（如 claude-opus）卡片上的「管理授权 →」
3. 抽屉打开后，默认在「工作室授权」Tab
4. 点击「部门开通」Tab

**预期结果**:
- 切换到「部门开通」Tab
- 顶部有两部分：
  - 「按工作室筛选」el-select（placeholder「按工作室筛选」，clearable）
  - 「**+ 开通部门**」按钮（primary，初始禁用）
- 表格区域显示部门开通记录

#### 测试 4.2: 未选工作室时「开通部门」禁用

**前置**: 在部门开通 Tab，未选工作室筛选

**预期结果**:
- 「+ 开通部门」按钮 disabled，hover 有 tooltip 提示「请先选择工作室」

#### 测试 4.3: 工作室筛选器列出所有已授权工作室

**步骤**: 点击「按工作室筛选」下拉

**预期结果**:
- 下拉选项 = 该受控组**已被授权**的工作室（不是系统全部工作室）
- 每个选项显示「{工作室名}」
- 支持 filterable 关键词检索

#### 测试 4.4: 选择工作室后表格刷新

**步骤**: 选择任一已授权工作室

**预期结果**:
- 「+ 开通部门」按钮 enabled
- 表格只显示该工作室下已开通的部门（如有）
- 空状态：「暂无开通部门」

#### 测试 4.5: 开通新部门

**步骤**:
1. 点击「+ 开通部门」
2. Dialog 弹出（标题「开通部门」）
3. 「选择部门」el-select（filterable）展开
4. 选择一个该工作室下的未开通部门
5. Dialog 内显示「所属工作室」只读文字
6. 点击「确定开通」

**预期结果**:
- ✅ success message：「已开通部门」
- ✅ Dialog 关闭
- ✅ 表格新增一行：部门名 / 所属工作室 / 开通人 / 开通时间 / 撤销按钮
- ✅ 抽屉外的受控组卡片：「🏬 N 部门开通」统计数 +1

#### 测试 4.6: 已开通部门在下拉中禁用

**前置**: 已有开通记录

**步骤**: 重新打开「开通部门」Dialog，展开部门下拉

**预期结果**:
- 已开通的部门在下拉中**显示 disabled** 或带「已开通」标记
- 其他未开通的部门可正常选择

#### 测试 4.7: 撤销部门开通

**步骤**: 点击某行的「撤销」按钮 → popconfirm 标题「确定撤销该部门开通？」→「确定」

**预期结果**:
- ✅ 红色 success message（或普通 success message）：「已撤销部门开通」
- ✅ 该行从表格消失
- ✅ 抽屉外卡片统计数 -1

#### 测试 4.8: 撤销确认时取消

**步骤**: popconfirm 出现后点击「取消」

**预期结果**: popconfirm 消失，行保持

#### 测试 4.9: 切换工作室筛选

**步骤**: 已选工作室 A，切换到工作室 B

**预期结果**:
- 表格刷新为空（或工作室 B 的已开通部门）
- 「+ 开通部门」仍然可用（已选工作室）

#### 测试 4.10: 清除筛选

**步骤**: 点击筛选器清除图标（x）

**预期结果**:
- 「+ 开通部门」按钮回到 disabled
- 表格显示所有已开通部门记录

### 第二部分：studio_admin 在自己工作室开通部门（4.11 - 4.16）

#### 测试 4.11: studio_admin 进入受控组卡片上的开通入口

**步骤**:
1. 使用 `studio_admin_b` 登录
2. 进入 `/admin/entitlements`
3. 在卡片视图中找到本工作室已获授权的受控组（如 claude-opus）
4. 点击卡片上的「管理部门开通 →」按钮（或「开通部门 →」）

**预期结果**:
- ✅ 不被 403
- ✅ 抽屉打开
- ✅ 抽屉标题格式「授权管理 — {组名}」
- ✅ 抽屉内**只有「部门开通」一个 Tab**（工作室授权 Tab 不可见）

#### 测试 4.12: studio_admin 抽屉内工作室筛选锁定

**前置**: 抽屉已打开（4.11）

**步骤**: 观察「部门开通」Tab 的筛选器

**预期结果**:
- 「按工作室筛选」el-select **显示本工作室名称为选中值**
- 该 el-select **disabled** 或 readonly（不可切换到其他工作室）
- 「+ 开通部门」按钮直接 enabled
- 表格直接显示本工作室下的部门开通记录

> **设计差异**：与 admin 不同，studio_admin 不需要手动选择工作室，系统自动锁定其管辖范围。

#### 测试 4.13: studio_admin 开通本工作室下的部门

**步骤**:
1. 点击「+ 开通部门」
2. Dialog 打开（标题「开通部门」）
3. 「选择部门」el-select 展开
4. 选择一个本工作室下未开通的部门（**非本部门也可，只要是本工作室下的**）
5. 点击「确定开通」

**预期结果**:
- ✅ success message：「已开通部门」
- ✅ 表格新增该行

**隔离验证**：
- 「选择部门」下拉中**只显示本工作室下的部门**
- 其他工作室的部门**不在选择列表中**

#### 测试 4.14: studio_admin 不能开通其他工作室的部门

**反例验证**: 重复 4.13 流程，观察部门下拉

**预期结果**:
- studio_admin 在部门下拉中**不可能选到其他工作室的部门**（前端已经过滤）
- 即便通过 API 直接调用，后端也应返回 `entitlement_forbidden`（403）

#### 测试 4.15: studio_admin 撤销本工作室下的部门开通

**步骤**: 在自己开通的记录旁点击「撤销」→ popconfirm →「确定」

**预期结果**:
- ✅ 撤销成功，表格消失该行，卡片统计 -1

#### 测试 4.16: studio_admin 不能撤销本工作室外的开通记录

**反例**: 尝试在表格中查看其他工作室的开通记录

**预期结果**:
- 表格中**不可能出现**其他工作室开通的数据（前端已经按 studio 过滤）
- 不存在「试图撤销他人开通」的 UI 路径

### 第三部分：dept_admin 开通本部门（4.17 - 4.22）

#### 测试 4.17: dept_admin 在双列布局页面看到「可开通」区

**步骤**:
1. 使用 `dept_admin_a` 登录
2. 导航到 `/admin/entitlements`
3. 观察页面布局

**预期结果**:
- 页面顶部显示**部门信息卡**：「我的部门: {dept_name}（所属: {studio_name}）」
- 卡片视图分为**两列**：
  - **左列「已可用」**：public 组 + 本部门已开通的 controlled 组
  - **右列「可开通」**：本工作室已获授权但本部门未开通的 controlled 组
- 每列卡片有不同视觉风格（左列绿色调 / 右列橙色调）

#### 测试 4.18: dept_admin 点击「可开通」区卡片的「开通本部门 →」按钮

**步骤**: 找到右列「可开通」区中 `claude-opus`（本工作室已获授权，本部门未开通）卡片，点击「开通本部门 →」按钮

**预期结果**:
- popconfirm 出现，标题「**确定为本部门开通 {组名}？**」
- 按钮「确定开通」 / 「取消」

#### 测试 4.19: dept_admin 一键开通本部门

**步骤**: 点击「确定开通」

**预期结果**:
- ✅ success message：「已开通本部门」
- ✅ 该卡片从右列「可开通」区**移动**到左列「已可用」区
- ✅ 卡片状态从 🟠 受控·待开通 → 🟢 受控·已开通

#### 测试 4.20: dept_admin 撤销本部门开通

**步骤**:
1. 在左列「已可用」区找到刚开通的 controlled 组卡片
2. 卡片右上角应有「撤销」icon button 或「撤销开通」文字按钮
3. 点击后 popconfirm「确定撤销本部门的开通？」
4. 点击「确定」

**预期结果**:
- ✅ success message：「已撤销部门开通」
- ✅ 该卡片从左列「已可用」区**移回**右列「可开通」区
- ✅ 卡片状态从 🟢 已开通 → 🟠 待开通

#### 测试 4.21: dept_admin 看不到本工作室未获授权的受控组

**步骤**: 查找 `gpt-4`（未授权给任何工作室）

**预期结果**:
- ✅ `gpt-4` 卡片**不在页面上任何位置**
- 不在「已可用」区
- 不在「可开通」区
- 无任何提示说「有组未授权」

#### 测试 4.22: dept_admin 开通/撤销范围仅限本部门

**步骤**: 在 dept_admin 视图里尝试开通「其他部门」

**预期结果**:
- UI 上**不存在**选择其他部门的入口
- dept_admin 所有「开通」操作都只能针对自己部门
- 即使通过抽屉 Tab 方式进入，抽屉内筛选和部门列表也是锁定为本部门所属工作室、仅显示本部门

### 第四部分：admin 视角下的 dept_admin 操作同步（4.23）

#### 测试 4.23: dept_admin 开通后，admin 视图可立即看到

**步骤**:
1. dept_admin_a 为本部门开通 `claude-opus`（完成 4.19）
2. admin 登录 → `/admin/entitlements`
3. 打开 `claude-opus` 卡片抽屉 → 「部门开通」Tab
4. 选择 studio_admin_b 所属工作室为筛选

**预期结果**:
- ✅ 表格中出现 dept_admin_a 所属部门的开通记录
- ✅ 「开通人」列显示 dept_admin_a 或该用户的显示名

## 关键 DOM 选择器提示

- 部门开通 Tab: `.el-tabs__item` label="部门开通"
- 按工作室筛选: `.el-select`（placeholder「按工作室筛选」）
- 开通部门按钮: 文字「+ 开通部门」或「开通部门」
- Dialog: `.el-dialog` 标题含「开通部门」或「开通本部门」
- 部门选择 el-select: placeholder「选择部门」
- 所属工作室只读文字: Dialog 内 `.dept-studio-name` 等
- 撤销按钮: 表格行中 type=danger 的 button 文字「撤销」
- Popconfirm「确定开通」: `.el-button--primary` 文字 「确定开通」或「确定」

## 验收标准

| # | 检查项 | 通过条件 |
|---|--------|---------|
| 1 | admin 全范围开通 | 选任意工作室、任意部门 |
| 2 | studio_admin 本工作室范围 | 工作室筛选锁定，只能选本工作室下的部门 |
| 3 | dept_admin 本部门范围 | 一键开通本部门，不可选其他部门 |
| 4 | 视图适配 | 三角色在抽屉/卡片中看到的 UI 均不同 |
| 5 | 撤销联动 | 撤销后抽屉表格 + 外部卡片统计同步减少 |
| 6 | 信息不泄露 | dept_admin 看不到本工作室未授权组，studio_admin 看不到其他工作室 |
| 7 | 操作同步性 | dept_admin 开通后 admin 立即可见 |
