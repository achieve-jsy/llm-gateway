# trace-mutate —— 分支级变异验证基础设施

**一分钟版本**：这是一把**通用的**「删掉某道防线，测试真的会红吗」检验器。
一个任务 = 一次调用；它先自证这一轮证据有效（清单全跑、全部有终判、SKIP=0、
子进程环境封闭），再逐条把守卫删掉/放宽、跑测试、报告是否转红。

它**不是** Task 6 的专用脚本。任务相关的四样东西全部由参数或集合文件给出，因此
Task 8、R11 以及分支收尾的「全任务证据重跑」都用同一个工具、同一套判据。

## 怎么跑

```bash
# 一个任务一次调用（非交互）；缺省 --packages/--target 取集合里声明的值
python3 tools/trace-mutate/trace_mutate.py \
    --repo . \
    --manifest .superpowers/sdd/<feature>/task-6-evidence/names.txt \
    --mutation-set tools/trace-mutate/sets/task-6.py
```

其它模式：

| 命令 | 用途 |
|---|---|
| `--check` | 只校验每条变异的模式在 `HEAD:<target>` 上**唯一定位**（不跑测试，秒级） |
| `--list` | 列出集合里的变异、静态检查、映射表 |
| `--mapping` | 只打印「计划要求 → 集合条目」映射表（追加 G 的可审计形式） |
| `--selftest` | 自证「无效证据检测」本身有效（7 组合成反例，期望退出码 0） |
| `--only m49 --side` | 对选中变异打印**完整双侧**原始输出（pristine 侧 + 变异侧） |
| `--only m01 m02` | 只跑子集（排障用；权威表必须跑全集） |
| `--keep-tree` | 保留 `git archive` 解出的 pristine 树并打印路径 |

**退出码**：0 = 全部变异转红（或有登记的「允许的绿」理由）+ 静态检查通过 +
清单推导一致 + 证据有效；1 = 以上任一条不成立。
`--side` 下若有证据无效**也会非零退出**（旧脚本打印「证据无效！」却退 0）。

## 产出什么

固定头部（**事实，不是声明**）：

- `git rev-parse HEAD`、`git status --porcelain`（**脏树直接拒绝运行**）
- 工具自身 / 变异集合 / 名字清单 三者的 sha256
- 名字清单的**推导命令**，以及「工具实际执行推导命令后的结果 vs 清单」的比对
- pristine 树来源（`git archive HEAD | tar -x`，**现取现解，不复用旧副本**）
- 被变异文件与全部 `*_test.go` 的 sha256
- 子进程实际拿到的环境变量白名单，以及父进程中被剔除的敏感变量名

然后是一张逐条表：`变异 → 判定 → 自证串（names/ran/diff/PASS/SKIP/FAIL）→ 杀死的用例`，
以及计数口径（断言支撑的红 / 崩溃超时红 / 允许的绿 / 未登记的绿 / 证据无效）。

## 集合文件（`sets/task-<N>.py`）—— 必须 git-tracked

判据是「**作者编写的产物进版本库，可推导的产物随地方便**」：

| 产物 | 可推导？ | 放哪 | 为什么 |
|---|---|---|---|
| 名字清单（用例名） | **是**（`grep '^func Test'`） | 可放证据目录（gitignored） | 工具会打印推导命令 + 哈希，并**实际重推比对** |
| 变异集合（哪些守卫本该被删） | **否** | **必须 git-tracked** | 树里没有任何东西能让第三方重算；留在 gitignored 空间时，作者可以悄悄删掉一条变异而 `git diff` 什么都看不到 |

集合文件声明的字段：

```python
NAME, TARGET, PACKAGES                 # 任务标识、被变异文件、go test 包列表
MANIFEST_FILES, MANIFEST_DERIVATION    # 清单来源 + 推导命令（工具会实际执行并比对）
SKIP_WHITELIST                         # 允许 SKIP 的用例（默认空 ⇒ 任何 SKIP 都判无效）
MUTATIONS = {名字: [("sub", a, b) | ("cut", a, b), ...]}
CHECKS = [{name, file, pattern, expect: absent|present, why}]   # 变异测不到的要求的静态检查行
REQUIREMENTS = [{plan, mutations, checks, note}]                # 映射表；有缺口则整轮失败
EXPECTED_GREEN = {变异名: 理由}   # 零覆盖必须在这里登记理由，未登记的绿 ⇒ 整轮失败
RETIRED = {编号: 理由}            # 已退役编号，登记备查
```

## 三条判据（为什么可信）

1. **证据绑定提交**：pristine 树由 `git archive HEAD` 现取现解；工作树脏即拒绝运行；
   打印 HEAD、树状态、工具/集合/清单/被测文件哈希 ⇒「这次跑的是哪棵树」是事实。
2. **工具、集合、清单三者出哈希**：谁改了集合，哈希就变；配合 git 跟踪，
   「悄悄丢掉一个变异」在 `git diff` 里可见，「这张表是哪个集合产出的」可复核。
3. **子进程封闭环境**：`go test` 只拿到白名单环境变量。`GOFLAGS` 一类变量必须剔除 ——
   它能在 `-exec` 下**整体替换测试输出**，把真红洗成全绿，甚至把**零覆盖伪装成有覆盖**，
   而且自证串逐字同形。白名单（而非黑名单）意味着新增变量必须显式批准。

> **信任根的边界（必须说清楚）**：没有任何仓内工具能阻止一个不诚实的作者。
> 上面三条的目标不是防作弊，而是让**篡改在事后可被发现**。不要宣称「已不可骗」。

## 三断言

每次运行都必须同时成立，否则该次运行判为「证据无效」：

1. 执行到的顶层用例集合 == 名字清单（且 `=== RUN` 行数 == 条数）
2. 顶层 `PASS + FAIL + SKIP` == 清单条数
3. **全层级** SKIP == 0（含缩进的子测试行；白名单在集合里声明）

外加两条「先判」（不是打印）：名字清单为空 ⇒ 无效；`no tests to run` ⇒ 无效。
