### 用户场景

- **场景 1**：员工创建 API Key 时，看到可选模型组列表并勾选需要的组，Key 创建后通过该 Key 调用 `/v1/models` 返回这些组名，请求时指定组名发起调用
- **场景 2**：管理员后续变更某 Key 的组绑定（增加或移除模型组），变更立即对新请求生效，进行中调用不受影响

## 3. 初步聚焦

### 推荐深入的方向

1. **Key↔模型组绑定**：核心连接点，打通 Key 和模型组的治理链路，让模型组成为业务方真正使用的"模型"概念
2. **模型组对业务方透明化**：`/v1/models` 只返回组名，调用方不感知底层模型和渠道，符合宪章原则七（分层抽象）

### 建议排除的方向

- **跨模型组负载均衡**：调用方主动选择目标组，不需要组间自动调度（排除）
- **组可见性权限过滤**：放到后续版本，本期所有已注册组全员可见
- **Key 组绑定审计**：放到后续版本
