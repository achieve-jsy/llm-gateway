# gateway-api 需求变更 — CHG-20260525-001

> 基线：xspec/modules/gateway-api/spec.md (v1.1)

## 变更摘要

引入模型组调用入口：业务方调用时传组名替代模型名，gateway-api 解析组名后委托 scheduler 选择组内目标模型，使用选中的模型完成实际调用。调用失败时触发故障切换，请求 scheduler 重新路由至同组其他健康模型。组名不存在或组内无可用模型时返回明确错误。

## 新增需求

### US-GROUP-INVOKE-01 — 组名调用入口 (P0)

**作为**业务开发团队，**我想要**调用时传入模型组名而非具体模型名，**以便**无需关心底层模型和渠道选择即可完成调用。

**功能说明**：
- 业务方调用统一入口时，请求中的模型标识字段传入组名
- gateway-api 解析到组名后，委托 scheduler 进行路由决策，获取同组内的具体目标模型
- gateway-api 使用 scheduler 返回的目标模型（含渠道信息）完成实际调用
- 调用成功后向业务方返回结果，与直接传模型名的行为语义一致

**异常与边界**：
- 传入的组名不存在 → gateway-api 在校验阶段直接返回"模型组不存在"错误，不经过 scheduler
- scheduler 返回该组无可用模型 → gateway-api 向业务方返回"该模型组当前无可用模型，请稍后重试"
- scheduler 不可用（宕机/超时）→ gateway-api 降级为选择组内首个注册模型直连调用

### US-GROUP-INVOKE-02 — 调用失败后自动切换 (P0)

**作为**业务开发团队，**我想要**组内模型调用失败时系统自动切换到其他可用模型，**以便**调用不因单个模型故障而中断。

**功能说明**：
- 使用 scheduler 选中的目标模型调用失败（超时、连接错误、服务端错误），gateway-api 请求 scheduler 进行故障切换
- scheduler 排除已失败的模型，从同组健康模型中重新选择新目标
- gateway-api 使用新目标重试调用，对业务方仅返回最终结果（成功或失败）
- 最多重试一次切换，避免在连续失败的组中陷入无限重试

**异常与边界**：
- 切换后新目标也调用失败 → 向业务方返回调用失败结果，不再继续重试
- 同组内已无其他可用模型 → 向业务方返回"该模型组当前无可用模型"
- 流式调用中途失败 → 流已中断，不切换重试（切换重试仅适用于尚未返回数据的失败场景）

### US-GROUP-INVOKE-03 — 组名调用与鉴权链路兼容 (P1)

**作为**系统，**我想要**组名调用与现有 API Key → User → Department 鉴权链路无缝兼容，**以便**组名调用不绕过身份追溯。

**功能说明**：
- 组名调用经过与模型名调用完全相同的鉴权中间件（API Key → User → Department）
- 调用日志中同时记录请求传入的组名和 scheduler 实际选中的目标模型标识
- 模型组可见性不做权限过滤（本次版本所有组对所有已认证用户可见）

**异常与边界**：
- 未认证的组名调用请求 → 鉴权中间件拦截，与模型名调用行为一致
- 组名调用的可用模型查询 → 返回当前认证用户有权访问的模型组列表，而非具体模型列表
